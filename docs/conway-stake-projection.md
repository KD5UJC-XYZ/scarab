# Checked Conway stake and snapshot slice

This is a pure module for the fixed-registration private Conway profile, not an epoch validator. The opt-in [atomic coordinator integration](atomic-stake-coordinator.md) now publishes this projection with the coherent tuple. Existing same-epoch runtime guards and all legacy adapters remain unchanged. No node command or CLI enables it; existing checkpoint codecs reject the enlarged tuple.

## APIs and ownership

`ConwayStakeSeed.decode(ledgerJson, ledgerSha256, wholeUtxoCbor, utxoSha256, epochLength)` produces a checked `Prepared` stake projection. It decodes account balances/deposits/delegations, the pool parameters relevant to staking and rewards (VRF, owners, delegators, pledge, cost, margin, reward account and deposit), exported instantaneous stake and historical mark/set/go snapshots. Each export snapshot is checked against its active stake under the fixed membership/pool-parameter fixture. Explicit empty historical snapshots remain empty. Changed historical registration/parameters are unsupported, not silently normalized. Complete source bytes remain digest-bound; metadata, relays, DRep/governance effects and pending rewards are not projected.

`Prepared.attach(owner, ledgerState)` binds the same complete UTxO, epoch and fees to a checked existing ledger state. `ConwayStake.context`, `seed`, `snapshot` and `fromActive` provide corresponding pure constructors. Constructors validate credential/hash widths, coin bounds, exact ratios and bidirectional agreement of account delegation with each pool's delegator set. The ledger slot must map to its named epoch using the supplied fixed epoch length. `epochLength` is supplied context: the caller must bind it to its checked genesis (as existing SequenceInput does); this adapter does not parse genesis or authenticate that assertion.

`ConwayStake.prepare(owner, state, ledgerBefore, checkedBlockCandidate)` evaluates `ClusterTransition.commitBlock` purely to verify the ledger predecessor and derive the accepted after-UTxO. It calculates net spent/created effects, rejects changed surviving references, incrementally updates credential totals, then compares against full recomputation. It accepts no caller-created spent/created delta. Empty blocks are supported. A strictly increasing same-epoch slot is mandatory.

`select(owner, currentState, candidate)` checks opaque owner identity, exact before-state ID and revision before returning the immutable projected state. Candidates also bind header hash, header slot and profile identity. Neither operation publishes runtime state. An enclosing coordinator must atomically select/publish the ledger, stake, certificate and nonce tuple, maintain its own revision fencing and own all undo/retention. There is deliberately no second stake rollback store. Pure values are not globally single-use capabilities; callers must not treat repeated selection against an unchanged historical value as a runtime commit.

`previewRotation(owner, state, headerHash, nextEpochSlot, fees)` performs only SNAP algebra: fresh mark from this state's instantaneous stake and frozen account balances, old mark to set, old set to go, supplied snapshot fees, and **old mark** as the next leadership snapshot. It binds before-ID/revision/header identity, is unpublished, and reports `epochTransitionValidated=false`. It cannot be selected as a new runtime epoch state. Its fee input is explicitly supplied for algebra tests; a future epoch coordinator must pass the correctly ordered post-reward fee pot. Do not use this preview as NEWEPOCH: rewards, pool reaping, governance and parameter rollover have not been applied.

- [Shelley Rules/Snap.hs](https://github.com/IntersectMBO/cardano-ledger/blob/f649f9751074d2ab3de033fc3912f29c9862c1f5/eras/shelley/impl/src/Cardano/Ledger/Shelley/Rules/Snap.hs) and [Conway Rules/NewEpoch.hs](https://github.com/IntersectMBO/cardano-ledger/blob/f649f9751074d2ab3de033fc3912f29c9862c1f5/eras/conway/impl/src/Cardano/Ledger/Conway/Rules/NewEpoch.hs): snapshot rotation and old-mark leadership selection.

All arithmetic is BigInt with Word64 coin/aggregate bounds and exact rational reduction; no floating conversion. Decimal margins parse through exact decimal integers. Stake decoding accepts bounded base address kinds 0–3 and enterprise 6–7 on the private network, including script staking credentials and multiasset output values. Only lovelace contributes stake. Pointer/Byron addresses, datum/reference-script outputs and malformed values are explicitly unsupported; this is narrower than general Conway. Supporting a form in stake decoding does not widen the existing ledger transaction admission profile.

## Seed and acquisition limits

Supply full ledger JSON plus a separately acquired `cardano-cli conway query utxo ... --whole-utxo --output-cbor-hex` result, decoded from hex before passing and hashing it. The retained ledger JSON's `utxo` map is omitted/empty and cannot substitute for that source. The adapter recomputes instantaneous stake across every supplied output and compares all credential totals with `utxoState.stake.credentials`. This detects omission of stake-bearing outputs but **cannot detect omitted enterprise outputs**. Completeness, same-chain attribution, fixed membership history, stable query brackets and authenticity remain acquisition assumptions. Retain original query bytes/manifests and source hashes; do not claim this check authenticates the whole UTxO set.

The initial fixed pool fixture rejects pending pool updates or retirements. Missing mandatory fields, mismatched balance/reward aliases, inconsistent delegator indexes, snapshot pool parameters/totals/owner contributions, wrong source pins, wrong ledger UTxO/epoch/fees, unsupported addresses, aggregate overflow and foreign/stale candidates fail closed.

`Prepared.rewardsDecoded=false`, `donationsKnown=false`, and `epochTransitionReady=false` are explicit. Non-null `possibleRewardUpdate` needs a lossless decoder of pulser inputs/phase or a proven equivalent semantic representation. Even null is only evidence about this one snapshot, not proof rewards remain absent. Same-epoch reward-start inputs must be frozen at the correct source trigger and never recomputed from later balances. Donation omission in the JSON cannot mean zero: future integration needs a lossless exporter (e.g. version-pinned ledger-state CBOR/canonical state exposing donations) or separately authenticated initialization plus a complete no-donation history proving zero. Governance proposals/enactments, parameter updates, automatic dormant counters, pool reaping and deposits need their own checked handling or supported exclusion proof. None of these gaps blocks this stake-only slice; all block epoch publication.

## Focused evidence

Public tests cover account-only rewards, unregistered/undelegated stake, self-delegated owners, zero-stake denominator and pool membership, script credentials, native asset quantities, unsupported forms, overflow, owner/revision fencing, unchanged state before selection, strict same-epoch admission, and old-mark leadership/mark-set-go rotation.

Opt-in tests use the separately retained private whole-UTxO sequence capture, replay accepted blocks and compare incremental totals with full recomputation and the independently pinned post ledger export. A separate explicitly synthetic test reuses an existing signed transaction against a supplied UTxO with the same payment credential but a new base staking credential; it exercises deletion of that credential's final stake without key generation/signing. It is not reference-state evidence. Raw private data remains outside Git.

No live cluster, full-suite checkpoint, reward implementation or runtime expansion is part of this change. Independent review is recorded in the external Markdown handoff.
