# Ledger: Conway transaction body and witness-set decoding at decoder version 9 (audit, AUD3-01/#327)

Part of the [compatibility matrix](../compatibility.md); the register entry is `ledger-conway-body-decoding-v9` in [compatibility.json](../data/compatibility.json). The three sections below are the cells of the former matrix row, unchanged.

## Status as recorded

implemented: `TxBody.decode` and `Witnesses.decode` take the era and read at its decoder version (`DecoderVersion`, `eraProtVerLow`: Conway 9, Babbage 7). From version 9 the sets of inputs, collateral, required signers and reference inputs, the ordered sets of certificates and proposals, the withdrawals, the voting procedures (voters, and actions of a voter) and the pool owners, committee members to remove and added, and treasury withdrawals inside them refuse a repeated element (`decodeSet`, `decodeMapByKey`, `decodeOSet`, cardano-ledger f649f975 `Decoder.hs`, `Data/OSet/Strict.hs`), judged on the decoded element so two encodings of one `TxIn` are one, and for the certificates and proposals on what the reference's derived `Ord` compares (`Semantic`: a pool's relays and metadata, a parameter update by its typed fields and treasury withdrawals by meaning, not by encoding); the parameter update of a Conway proposal is the Conway `PParamsUpdate` (`ConwayParamUpdate`, `Core/PParams.hs:257-293`, `Conway/PParams.hs:643-709, 862-894`): only the Conway update keys (not 12 to 15, not 34 and up), each value at its field's type and width, and a repeated key refused before its value is read (`applyField`, `Coders.hs:562-570`), so enacting a ratified change applies the typed update and cannot fail; a rational (tag 30) is read as the reference does below decoder version 12 (`decodeRationalWithTag`, `Binary/Plain.hs:155-163`; `BoundedRatio`, `BaseTypes.hs:348-374, 416-430`): integers of any sign or size (bignums only from the one-byte heads `c2`/`c3` over a definite string, as cborg reads them), a zero denominator refused, the reduced value bounded to the field's interval (`UnitInterval` for a margin, quorum, rho, tau, d and voting thresholds; `NonNegativeInterval` for a0, prices and the reference-script fee) in `CborRead.rational`, `ProtocolParams.update`, `LiteLedger.applyUpdate` and `ScriptContexts.changedParameters`; tag 258 is read only from version 9 (`allowTag`), and below it a tagged list is refused; Conway refuses a present empty certificates (4), withdrawals (5), mint (9), collateral (13), required signers (14), reference inputs (18), voting procedures (19) and proposals (20), a zero donation (22), a voter without votes, and key 6 (`Conway/TxBody.hs` `bodyFields`, `fieldGuarded`, `decodePositiveCoin`; `Governance/Procedures.hs`); the witness set at versions 9 to 11 refuses an empty vkey, bootstrap, native script, Plutus script, datum or redeemer list (`Alonzo/TxWits.hs` `addrWitsSetDecoder`, `nativeScriptsDecoder`, `scriptDecoderV9`, `TxDatsRaw`, `RedeemersRaw`) and a Plutus script listed twice under one language, and tolerates repeated vkeys, bootstrap witnesses, native scripts, datums and redeemer keys; below version 9 the redeemers are read as a list only

## Explicitly unchecked or unconfirmed

pre-Conway eras keep their previous list and field rules except that tag 258 and the map form of redeemers are not read and sets collapse by decoded value below version 9 (next row); the Alonzo and Babbage empty-list and duplicate rules and the Shelley witness-set key set are not ported (#374); a chunked byte string is the row after next (#373); the multi-asset (mint) amount rules are #328; version 12 (Dijkstra) is not decoded; ADR 0006 continuation: a V5 state written before rationals were bounded can hold a pending update the reference could not have decoded (a `d` of 3/2). It loads and is written again unchanged with the update verbatim, and the update is no longer adopted: `UpdateChecks.voted` gives none for an update that cannot be read, as it already did for any unreadable field, and `LiteLedger` returns the typed `RationalOutOfBounds`. A typed refusal through `UpdateChecks.voted` would change the signature of UPEC and PPUP and is not made here; no such state is known on a public network, since the reference refuses the block that would carry the update (`SnapshotV5Suite`, parameter updates outside their interval). A Conway parameter-change proposal in the Haskell section is different: it is read through the Conway decoder on load (the persisted bytes are unchanged, so the snapshot keeps its format: the V5 body inside the V7 envelope), and a stored proposal that is not a Conway `PParamsUpdate` refuses the load with the typed `UnknownKey`, `DuplicateKey` or value error, because keeping it would bring back an enactment that can fail; only a node that accepted a block the reference refused can hold one, and it recovers from an earlier snapshot or a resync (`HaskellStateCodecSuite`); a pre-Conway update proposal (key 6) is read at its era's update keys (Shelley to Mary 0 to 16, Alonzo 0 to 14 and 16 to 24, Babbage 0 to 11, 14 and 16 to 24; `Shelley/PParams.hs`, `Alonzo/PParams.hs`, `Babbage/PParams.hs`) with a repeated key refused (`UnknownKey`, `DuplicateKey`; `PreConwaySetsReferenceSuite`), but its values other than the cost models are still read only when the update is applied, and a stored pending update keeps the load rule above
