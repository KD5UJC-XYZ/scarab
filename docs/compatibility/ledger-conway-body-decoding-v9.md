# Ledger: Conway transaction body and witness-set decoding at decoder version 9 (audit, AUD3-01/#327)

Part of the [compatibility matrix](../compatibility.md); the register entry is `ledger-conway-body-decoding-v9` in [compatibility.json](../data/compatibility.json). The three sections below are the cells of the former matrix row, unchanged.

## Status as recorded

implemented: `TxBody.decode` and `Witnesses.decode` take the era and read at its decoder version (`DecoderVersion`, `eraProtVerLow`: Conway 9, Babbage 7). From version 9 the sets of inputs, collateral, required signers and reference inputs, the ordered sets of certificates and proposals, the withdrawals, the voting procedures (voters, and actions of a voter) and the pool owners, committee members to remove and added, and treasury withdrawals inside them refuse a repeated element (`decodeSet`, `decodeMapByKey`, `decodeOSet`, cardano-ledger f649f975 `Decoder.hs`, `Data/OSet/Strict.hs`), judged on the decoded element so two encodings of one `TxIn` are one, and for the certificates and proposals on what the reference's derived `Ord` compares (`Semantic`: a pool's relays and metadata, a parameter update's fields and treasury withdrawals by meaning, not by encoding); a rational (tag 30) is read as the reference does below decoder version 12 (`decodeRationalWithTag`, `Binary/Plain.hs:155-163`; `BoundedRatio`, `BaseTypes.hs:348-374, 416-430`): integers of any sign or size (bignums only from the one-byte heads `c2`/`c3` over a definite string, as cborg reads them), a zero denominator refused, the reduced value bounded to the field's interval (`UnitInterval` for a margin, quorum, rho, tau, d and voting thresholds; `NonNegativeInterval` for a0, prices and the reference-script fee) in `CborRead.rational`, `ProtocolParams.update`, `LiteLedger.applyUpdate` and `ScriptContexts.changedParameters`; tag 258 is read only from version 9 (`allowTag`), and below it a tagged list is refused; Conway refuses a present empty certificates (4), withdrawals (5), mint (9), collateral (13), required signers (14), reference inputs (18), voting procedures (19) and proposals (20), a zero donation (22), a voter without votes, and key 6 (`Conway/TxBody.hs` `bodyFields`, `fieldGuarded`, `decodePositiveCoin`; `Governance/Procedures.hs`); the witness set at versions 9 to 11 refuses an empty vkey, bootstrap, native script, Plutus script, datum or redeemer list (`Alonzo/TxWits.hs` `addrWitsSetDecoder`, `nativeScriptsDecoder`, `scriptDecoderV9`, `TxDatsRaw`, `RedeemersRaw`) and a Plutus script listed twice under one language, and tolerates repeated vkeys, bootstrap witnesses, native scripts, datums and redeemer keys; below version 9 the redeemers are read as a list only

## Evidence

`ConwayDecodingReferenceSuite`: 222 original encodings (147 Conway bodies, 65 witness sets, 4 whole transactions, 6 Babbage bodies), each recorded with what the unchanged released decoders did with it (`fixtures/reference/conway-decoding`, oracle `scripts/oracle/conway-decoding`): 110 refusals, each for the rule the case breaks, and 112 accepted twins and tolerated duplicates; the same bytes are one input in Babbage and a refusal in Conway

## Explicitly unchecked or unconfirmed

pre-Conway eras keep their previous list and field rules except that tag 258 and the map form of redeemers are not read and sets collapse by decoded value below version 9 (next row); the Alonzo and Babbage empty-list and duplicate rules, the Shelley witness-set key set, parameter-update map duplicates and an indefinite-length byte string where the reference reads a definite one (hashes, scripts) are not ported; the multi-asset (mint) amount rules are #328; version 12 (Dijkstra) is not decoded; ADR 0006 continuation: a V5 state written before rationals were bounded can hold a pending update the reference could not have decoded (a `d` of 3/2). It loads and is written again unchanged with the update verbatim, and the update is no longer adopted: `UpdateChecks.voted` and `Ratify.enact` give none for an update that cannot be read, as they already did for any unreadable field, and `LiteLedger` returns the typed `RationalOutOfBounds`. A typed refusal through `UpdateChecks.voted` would change the signature of UPEC and PPUP and is not made here; no such state is known on a public network, since the reference refuses the block that would carry the update (`SnapshotV5Suite`, parameter updates outside their interval); the parameter-update fields are still not validated when a body is decoded
