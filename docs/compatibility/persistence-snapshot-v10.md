# Persistence: ledger snapshot format (V10) and the reference build

Part of the [compatibility matrix](../compatibility.md); the register entry is `persistence-snapshot-v10` in [compatibility.json](../data/compatibility.json).

## Status as recorded

implemented: native V10 (`SCRBSNPA`, #826) is the V9 layout ([V9](persistence-snapshot-v9.md)) with the reference build whose layout its Haskell state bytes are in recorded after the magic: a length byte and the `--reference-build` name, before the binding, outside the fingerprinted binding and sidecar schemas. The build is read before anything else because it decides the codec of the state bytes. `--reference-build` (on `follow`, `import-ledger-snapshot` and `export-ledger-snapshot`, `11.1` without it) names the build of `cardano-node` the network runs: `11.1`, the stable 11.1 release line behaving as its pinned release 11.1.3, or `leios-b004fe0c`, the unstable public Leios testnet build, which this build refuses at start because its layout is not implemented yet. The registered V9 → V10 step records `11.1` and keeps the binding, the sidecar and the Haskell bytes byte for byte: every V9 writer encodes with the 11.1 codec or keeps bytes that codec decoded completely, and that codec refuses a Dijkstra state (`DijkstraNotYet.LedgerState`) and the Leios build's three-part `ExtLedgerState`, as the reference's 11.1 decoder does (ouroboros-consensus 82ecba32 `Ledger/Extended.hs:268-280`). Import keeps the input `state` bytes and records the build that wrote them; input that does not decode completely in that build's layout is refused. Export writes the recorded bytes unchanged and names their build; a requested build of another layout is refused. Nothing is converted between builds. The restore's fallback mirrors the reference's `tryNewestFirst` case by case: too-recent and undecodable snapshots, those of another build and those whose checkpoint keys do not decode among them, are deleted with their checkpoints, best effort; those of another checkpoint layout or sidecar schema are kept; what the reference raises (an unreadable file, an absent checkpoint, an unknown Scarab format version) stops the start and deletes nothing. The migration of previous files takes the same fallback, and the V9 to V10 step copies everything after the magic as it was.

## Evidence

`fixtures/snapshot-v10` holds the registered conversions of the 17 `fixtures/snapshot-v9` files, each the V9 file with the five bytes of the `11.1` record after the magic; `SnapshotGoldenSuite` re-derives every one byte for byte, checks the binding, sidecar and Haskell bytes against the source, and migrates the V5, V7, V8 and V9 goldens once, all ending at the same V10 bytes. `CodecSuite` pins the header bytes of both builds; the sidecar and binding fingerprints are those of V9. `SnapshotV10MigrationSuite`: committed V9 files migrate once to the maintained V10 files and read as them; the 11.1 codec refuses a three-part `ExtLedgerState` and trailing bytes; a V10 file recorded under `leios-b004fe0c` or an unknown name is refused before its state bytes are read; a restore skips such a file, with an error naming both builds, and takes an older snapshot or none. `LedgerSnapshotImportSuite` and `LedgerSnapshotExportSuite`: the recorded and reported build, the refused undecodable input, the refused export of another build's snapshot, and the export of a V9 file not yet migrated; `SclsBaseSuite` exports the same SCLS artifact from a V9 base not yet migrated, read in memory. `ReferenceBuildStartSuite`: `follow --reference-build leios-b004fe0c` exits 1 before the database is touched. `ReferenceBuildSuite`: the names, the pins against `docs/data/reference-pins.json`, the startup refusal and the warning without `ExperimentalHardForksEnabled`.

## Explicitly unchecked or unconfirmed

The Leios build's layout is not implemented (#826 step b), and its rules are not selected by the build yet (step c). A snapshot recorded under another build is treated as the reference treats one it cannot decode: skipped with a warning naming both builds, deleted with its checkpoint (every native snapshot is temporary in the reference's sense) and the next older one tried (ouroboros-consensus 82ecba32 `Storage/LedgerDB/API.hs:599-646`; `SnapshotFallbackSuite` tests each case). In this build a snapshot of another build is reachable only in tests. Preprod/mainnet writer upgrades remain #129 and #37/#115.
