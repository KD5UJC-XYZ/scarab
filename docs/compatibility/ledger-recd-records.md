# Ledger: RecD records are definite lists, decoder versions 2 to 9 (#668)

Part of the [compatibility matrix](../compatibility.md); the register entry is `ledger-recd-records` in [compatibility.json](../data/compatibility.json). The sections below record the implementation, evidence and remaining limits.

## Status as recorded

implemented: below decoder version 12 the reference decodes a `RecD` record through `decodeCount (RecD cn) n`, which reads the length with `decodeRecordNamed` around a decoder that reads nothing (`Decoding/Coders.hs:482`, cardano-ledger `f649f975`), so a non-empty indefinite list fails with "Excess terms in array" (`decodeListLikeT`, `Decoding/Decoder.hs:690-708`). `CborRead.record` reads such a record as a definite list only and refuses the indefinite one with the typed `IndefiniteLength`. It reads the update proposal of a body (`Update`, `Shelley/PParams.hs:267`, Shelley to Babbage, in `TxBody.decode` and `LiteLedger.effects`), a redeemer's execution units (`ExUnits`, `Plutus/ExUnits.hs:195-215`, Alonzo to Conway, with the reader of the parameters' units, so a unit is a `Word64` at most `maxBound :: Int64`), Conway's `GovActionId` (whose index is a `Word16`), `VotingProcedure`, `ProposalProcedure`, `Constitution` and `Anchor` (`Conway/Governance/Procedures.hs`, `BaseTypes.hs:996-1004`), the `[coin, multiasset]` value of an output and of a collateral return (`MaryValue`, Mary to Conway: `decodeMaryValue` peeks the token type and sends an indefinite list to the `RecD` of `decodeValuePair`, `Mary/Value.hs:287-311`), and the `[metadata, native scripts]` list of auxiliary data (`AllegraTxAuxDataRaw`, Allegra and Mary; from Alonzo the `decodeAllegra` that `decodeTxAuxDataByTokenType` picks for a list, `Alonzo/TxAuxData.hs:245-251, 302-312`). The original bytes of an accepted body, witness set or transaction are kept.

An output's value is also read back from its original bytes: the UTxO store (`TxOut.fromBytes`, value tag 1) and the SCLS import (`UtxoCodecs.txOut`) read an output in `TxOut.Forms.Stored`, whose `ConwayParam.Records.Stored` takes the value as a definite or an indefinite list, so an output an earlier build took from a body and stored still loads (ADR 0006); a block reads its outputs in the era's forms, whose `Records.Body` refuses the indefinite list. The native snapshot and the MemPack import decode a value of their own structure and do not read this list. No other of these readers loads stored data: the governance state has its own codec, a pre-Conway update is stored as its parameter values, and no store holds auxiliary data.

A `RecD` record written as an empty indefinite list `9f ff` is read as the reference reads it: its break passes the reference's check, its fields are read from the items after the break (`ApplyD`, `Coders.hs:499-502`), and every enclosing decoder counts it as one item (#687). `DetachedRecords` walks a block, a body, a witness set, auxiliary data, a whole transaction or a stored output as the reference's decoders read it and lists such records; the read decodes as before and, when that refuses or the input holds an empty indefinite list, decodes again with the records framed as the reference frames them (`Cbor.Detached`), so the parts, the transaction ids and the block body hash span the bytes the reference reads. Only `CborRead.record` and the stored rule take a detached record; a parameter update keeps one as a definite list of its fields' original bytes.

A whole transaction, reached through submission only, is read by `Tx.envelopeParts` for `Tx.fromEnvelope`, the mempool (`MempoolState.parseParts`) and the forger. Before Alonzo it is the `RecD` record `ShelleyTx` (`Shelley/Tx.hs:184-192`): `CborRead.record` takes a definite list of three or the detached record and refuses a non-empty indefinite list with `IndefiniteLength` (#688). From Alonzo it is `decodeRecordNamed "AlonzoTx"` (`Alonzo/Tx.hs:532-553`), definite or indefinite: the third item is the validity flag when it is a boolean, the list then holding four items, and otherwise the auxiliary data of a valid transaction of three (#699); the node-to-node transaction submission's reader (`RelayedTransactions`, #702) reads it with `Tx.envelopeParts` too, so `TxSubmission2.bodyId` takes the same members. The mempool holds and relays a transaction as the reference relays it, `Tx.envelope`: `toCBORForMempoolSubmission` (`Alonzo/Tx.hs:489-513`), a definite list of four with the flag written and the other parts' original bytes, however it was submitted.

A Babbage or Conway block header is a Praos header, whose `HeaderRaw` and `HeaderBody` are `RecD` records (`libs/cardano-protocol/src/Cardano/Protocol/Praos/BlockHeader.hs:203-229`): `Header.fromRaw` reads them with `CborRead.record` through `DetachedRecords` (`Shapes.header`), and a block's header is framed so (#698).

A Leios block follows the build the public Leios testnet runs, the Leios reference since 2026-11-03 (#711; cardano-node `b004fe0c`, cardano-ledger `9df9f98c`, ouroboros-consensus `2416493b`, [leios.md](../leios.md) section 12). There it is read at Dijkstra's decoder version 12, where no list of a block is a `RecD` record: the block, its body and each transaction are `decodeRecordNamed` (`eras/dijkstra/impl/src/Cardano/Ledger/Dijkstra/Block.hs:34-42`, `BlockBody/Internal.hs:191-208`, `Tx.hs:175-182`), the Leios header, its body, version info and endorser block announcement too (`libs/cardano-protocol/src/Cardano/Protocol/Leios/BlockHeader.hs:308-344`, `libs/cardano-ledger-core/src/Cardano/Ledger/Block.hs:163-166, 184-189`), and each `RecD` record a transaction can hold is read by `decodeRecordNamed` from version 12 (`ifDecoderVersionAtLeast (natVersion @12)`, e.g. `Mary/Value.hs:308-321`). So each list is definite, or indefinite with its fields before the break, and one written as an empty indefinite list with its fields after it is refused. `LeiosBlock.decode` reads a block of tag 8 so, as a tree of items, behind the definite envelope of `decodeDiskHfcBlock` (consensus `Cardano/Node.hs:174-199`); a block of tag 7 is a Conway block with a Praos header there and is not a Leios block. `LeiosHeader.decode` reads the header so, its VRF certificate as `decodeRecordNamed` with an output of 64 bytes (`Decoding/DecCBOR.hs:627-652`), and its KES signature is over the header body's original bytes (`getSignableRepresentation = originalBytes`, `Leios/BlockHeader.hs:164-165`). The block's certificate is read as `DecCBOR LeiosCert` reads it (`decodeRecordNamed`, byte strings definite or chunked, signers at most 8,192 bytes; `Decoding/DecCBOR.hs:721-736`). A transaction's parts are kept as their bytes; the Dijkstra transaction rules are not implemented (the `dijkstra` component, roadmap L1). A TPraos header (Shelley to Alonzo) is read by `decodeRecordNamed`, definite or indefinite and never detached (`TPraos/BlockHeader.hs:193-241`); a VRF certificate is a definite list in every era (`enforceSize`), the body size and the minor version a `Word32`, and the major a `Version` up to 13. The header hash is over the original bytes; the KES signature is checked over the header body encoded again (`getSignableRepresentation`, `Praos/BlockHeader.hs:113-117`, `TPraos/BlockHeader.hs:170-171`), which `HeaderBodyEncoding` writes and the forger signs. A VRF output is a byte string of any length (`OutputVRF`, `Decoding/DecCBOR.hs:564-565`), refused by the VRF check when it is not the proof's (`verifyCertified`, cardano-crypto-class 2.5.1.0 `VRF/Class.hs:359-369`; Praos `VRFKeyBadProof`, consensus `Protocol/Praos.hs:587-592`; TPraos `VRFKeyBadNonce` and `VRFKeyBadLeaderValue`, `TPraos/Rules/Overlay.hs:168-184`), and chain selection orders outputs as `OutputVRF`'s derived `Ord` does, by length first (#712).

## Evidence

`RecdRecordsReferenceSuite`: 118 original encodings (`fixtures/reference/recd-records/cases.jsonl`, oracle `scripts/oracle/conway-decoding/recd_cases.py`), each record definite and indefinite in every era that reads it from a block, the redeemer's units at and over their bounds and the action index at and over its bound. 46 accepted, 72 refused, each refusal recorded with the fragment of the reference failure. Each record is also refused in the reference's order, before its fields: an indefinite list with a field of the wrong type at its break, and a definite list of three at its size. The value is in an output of two and of three items, a map output and a collateral return; the auxiliary data in a whole transaction of each era (the harness gained the transaction decoders of Allegra to Babbage for this). The suite also reads each output whose value a body refuses with the stored rule, which keeps its bytes and gives the value of the definite list, and `StoredChunkedOutputSuite` reads such an output back from the UTxO store while a Mary-to-Conway body that holds it is refused.

`DetachedRecordsReferenceSuite`: 202 original encodings (`fixtures/reference/recd-detached/cases.jsonl`, oracle `scripts/oracle/conway-decoding/detached_cases.py`) of each record written as `9f ff` with its fields after it, in bodies, witness sets, auxiliary data, whole transactions and block bodies of every era from Shelley to Conway, with the refusals around them; 146 accepted, 56 refused, and for each accepted body, transaction and block body the transaction ids and block body hash the reference hashes. Without the second read 134 of the accepted cases are refused. `RelayedTransactionsSuite` reads the Conway transactions of that corpus through the node-to-node transaction submission (#702): its codec takes each accepted one, in a reply it reads and one it sends, under the reference's id, and the mempool reads it alike. The codec reads a reply's transaction whole with the ledger's decoders, as the reference's codec does, so it refuses each transaction they refuse and the session ends as a codec failure ends it there (#708); every whole Conway transaction of the reference corpora gets the reference's verdict from it. `NtcQueryRecordsSuite` reads that corpus's sets of `GovActionId`, the one `RecD` record a node-to-client query carries (`GetProposals`), as the query does, bare and under `GetCBOR`, and frames each `MsgQuery` where the reference's decoder of queries ends it, the parts of a message as a mux delivers them waiting for the rest (#700): 12 sets, 6 accepted and 6 refused, among them an index over a `Word16` and a transaction id of 31 bytes, which the reference refuses and `NtcQuery` now refuses too. An answer that writes an output writes it decoded, so a detached value is `[coin, multiasset]` there as in the reference: the `detached` cases of the UTxO answers corpus (`UtxoAnswersReferenceSuite`, `DetachedOutputFailureSuite`). `DetachedRecordsSuite` covers the walk (its refusals, a 200,000-deep input on a small stack), the readers of a detached record, a stored output read again and a parameter update kept; `CborDetachedSuite` the decode.

`TxEnvelopeReferenceSuite`: 91 original encodings of a whole transaction (`fixtures/reference/tx-envelope/cases.jsonl`, oracle `scripts/oracle/conway-decoding/tx_envelope_cases.py`) of every era from Shelley to Conway, 43 accepted and 48 refused: before Alonzo the definite, non-empty indefinite and detached record and the wrong counts; from Alonzo four items with the flag and three without, definite and indefinite, with each form of auxiliary data, and the refusals (a boolean third item with nothing after it, a non-boolean third of four, the wrong counts, heads that disagree with the items, a detached envelope). For each accepted one the harness records the transaction id and the transaction's `encCBOR`, the bytes the reference relays; `Tx.envelope` of the parts read gives them from Alonzo. `TxEnvelopeSubmissionSuite` runs the Conway lines through the mempool's reading; `MempoolInterventionSuite` admits a recorded Plutus transaction without its flag and in an indefinite list, holds it valid (or, from a peer, invalid when its script fails), relays the definite list of four and gives the forger its parts; `TxSubmission2Suite` covers `bodyId`.

`HeaderDecodingReferenceSuite`: 120 original encodings (`fixtures/reference/header-decoding/cases.jsonl`, oracle `scripts/oracle/header-decoding/header_cases.py`, the released `cardano-protocol` 0.1.0.0 and `cardano-protocol-tpraos` 1.6.0.0) of Shelley, Alonzo, Babbage and Conway headers, header bodies and blocks, definite, indefinite, detached and with non-minimal heads, and VRF outputs of other lengths; 70 accepted, 50 refused (its 25 Leios cases moved to the Leios testnet corpus below on 2026-11-03), and for each accepted one the header hash, a block's body hash and the bytes the KES signature is checked over, which Scarab must sign the same. Two more lines run the released `verifyCertified` on a real VRF key's certificate with its output replaced (empty, one byte longer, one shorter), which decodes and is refused in each case but the evaluated output (#712); Scarab's VRF check gives the same verdicts. The suite also signs a header body in three non-canonical forms with a KES key of its own: the signature over the canonical encoding checks and the one over the original bytes does not.

`LeiosTestnetBlockReferenceSuite`: 86 original encodings (`fixtures/reference/leios-testnet-blocks/cases.jsonl`, oracle `scripts/oracle/leios-testnet/leios_cases.py`, built from the testnet build's ledger and cardano-base revisions): the testnet's blocks as BlockFetch carries them (five of the network as restarted on 2026-10-18), a block of synthetic transactions and the certifying block with each list in another form (the envelope, the block, the header and its body, the block body, the transaction list and a transaction, the Leios and Peras certificates), the certificate's signature of the wrong length, off the curve, outside the subgroup, not compressed and the identity, a tag-7 Conway block with a Praos header (accepted) and with a Leios header (refused), blocks of synthetic transactions whose output value is definite, indefinite or detached in each output form, and Leios headers alone in the forms of the header oracle, including issuer keys after 244 and 4000 empty chunks; 43 accepted and 43 refused. For each accepted one Scarab reads the same header hash, header size, signed bytes and header fields, block body hash and size, transaction ids and validity flags, and certificates. The record-form variants accept indefinite lists and refuse detached ones; the outer block envelope requires a definite list.

## Explicitly unchecked or unconfirmed

Nothing for the records themselves. The Leios reference's transactions are not decoded beyond their four parts (Dijkstra transaction rules, roadmap L1).
