# Ledger: RecD records are definite lists, decoder versions 2 to 9 (#668)

Part of the [compatibility matrix](../compatibility.md); the register entry is `ledger-recd-records` in [compatibility.json](../data/compatibility.json). The sections below record the implementation, evidence and remaining limits.

## Status as recorded

partial: below decoder version 12 the reference decodes a `RecD` record through `decodeCount (RecD cn) n`, which reads the length with `decodeRecordNamed` around a decoder that reads nothing (`Decoding/Coders.hs:482`, cardano-ledger `f649f975`), so a non-empty indefinite list fails with "Excess terms in array" (`decodeListLikeT`, `Decoding/Decoder.hs:690-708`). `CborRead.record` reads such a record as a definite list only and refuses the indefinite one with the typed `IndefiniteLength`. It reads the update proposal of a body (`Update`, `Shelley/PParams.hs:267`, Shelley to Babbage, in `TxBody.decode` and `LiteLedger.effects`), a redeemer's execution units (`ExUnits`, `Plutus/ExUnits.hs:195-215`, Alonzo to Conway, with the reader of the parameters' units, so a unit is a `Word64` at most `maxBound :: Int64`), Conway's `GovActionId` (whose index is a `Word16`), `VotingProcedure`, `ProposalProcedure`, `Constitution` and `Anchor` (`Conway/Governance/Procedures.hs`, `BaseTypes.hs:996-1004`), the `[coin, multiasset]` value of an output and of a collateral return (`MaryValue`, Mary to Conway: `decodeMaryValue` peeks the token type and sends an indefinite list to the `RecD` of `decodeValuePair`, `Mary/Value.hs:287-311`), and the `[metadata, native scripts]` list of auxiliary data (`AllegraTxAuxDataRaw`, Allegra and Mary; from Alonzo the `decodeAllegra` that `decodeTxAuxDataByTokenType` picks for a list, `Alonzo/TxAuxData.hs:245-251, 302-312`). The original bytes of an accepted body, witness set or transaction are kept.

An output's value is also read back from its original bytes: the UTxO store (`TxOut.fromBytes`, value tag 1) and the SCLS import (`UtxoCodecs.txOut`) read an output in `TxOut.Forms.Stored`, whose `ConwayParam.Records.Stored` takes the value as a definite or an indefinite list, so an output an earlier build took from a body and stored still loads (ADR 0006); a block reads its outputs in the era's forms, whose `Records.Body` refuses the indefinite list. The native snapshot and the MemPack import decode a value of their own structure and do not read this list. No other of these readers loads stored data: the governance state has its own codec, a pre-Conway update is stored as its parameter values, and no store holds auxiliary data.

## Evidence

`RecdRecordsReferenceSuite`: 118 original encodings (`fixtures/reference/recd-records/cases.jsonl`, oracle `scripts/oracle/conway-decoding/recd_cases.py`), each record definite and indefinite in every era that reads it from a block, the redeemer's units at and over their bounds and the action index at and over its bound. 46 accepted, 72 refused, each refusal recorded with the fragment of the reference failure. Each record is also refused in the reference's order, before its fields: an indefinite list with a field of the wrong type at its break, and a definite list of three at its size. The value is in an output of two and of three items, a map output and a collateral return; the auxiliary data in a whole transaction of each era (the harness gained the transaction decoders of Allegra to Babbage for this). The suite also reads each output whose value a body refuses with the stored rule, which keeps its bytes and gives the value of the definite list, and `StoredChunkedOutputSuite` reads such an output back from the UTxO store while a Mary-to-Conway body that holds it is refused.

## Explicitly unchecked or unconfirmed

An empty indefinite list passes the reference's check for the break, which then reads the record's fields from the items after it and can accept the body or witness set; Scarab parses a tree of items and refuses it ([#687](https://github.com/KD5UJC-XYZ/scarab/issues/687)). The Shelley-to-Mary transaction envelope, reached through transaction submission rather than a block, is [#688](https://github.com/KD5UJC-XYZ/scarab/issues/688).
