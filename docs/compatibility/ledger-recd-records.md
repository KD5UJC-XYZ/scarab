# Ledger: RecD records are definite lists, decoder versions 2 to 9 (#668)

Part of the [compatibility matrix](../compatibility.md); the register entry is `ledger-recd-records` in [compatibility.json](../data/compatibility.json). The sections below record the implementation, evidence and remaining limits.

## Status as recorded

partial: below decoder version 12 the reference decodes a `RecD` record through `decodeCount (RecD cn) n`, which reads the length with `decodeRecordNamed` around a decoder that reads nothing (`Decoding/Coders.hs:482`, cardano-ledger `f649f975`), so a non-empty indefinite list fails with "Excess terms in array" (`decodeListLikeT`, `Decoding/Decoder.hs:690-708`). `CborRead.record` reads such a record as a definite list only and refuses the indefinite one with the typed `IndefiniteLength`. It reads the update proposal of a body (`Update`, `Shelley/PParams.hs:267`, Shelley to Babbage, in `TxBody.decode` and `LiteLedger.effects`), a redeemer's execution units (`ExUnits`, `Plutus/ExUnits.hs:195-215`, Alonzo to Conway, with the reader of the parameters' units, so a unit is a `Word64` at most `maxBound :: Int64`), Conway's `GovActionId` (whose index is a `Word16`), `VotingProcedure`, `ProposalProcedure`, `Constitution` and `Anchor` (`Conway/Governance/Procedures.hs`, `BaseTypes.hs:996-1004`), the `[coin, multiasset]` value of an output and of a collateral return (`MaryValue`, Mary to Conway: `decodeMaryValue` peeks the token type and sends an indefinite list to the `RecD` of `decodeValuePair`, `Mary/Value.hs:287-311`), and the `[metadata, native scripts]` list of auxiliary data (`AllegraTxAuxDataRaw`, Allegra and Mary; from Alonzo the `decodeAllegra` that `decodeTxAuxDataByTokenType` picks for a list, `Alonzo/TxAuxData.hs:245-251, 302-312`). The original bytes of an accepted body, witness set or transaction are kept.

An output's value is also read back from its original bytes: the UTxO store (`TxOut.fromBytes`, value tag 1) and the SCLS import (`UtxoCodecs.txOut`) read an output in `TxOut.Forms.Stored`, whose `ConwayParam.Records.Stored` takes the value as a definite or an indefinite list, so an output an earlier build took from a body and stored still loads (ADR 0006); a block reads its outputs in the era's forms, whose `Records.Body` refuses the indefinite list. The native snapshot and the MemPack import decode a value of their own structure and do not read this list. No other of these readers loads stored data: the governance state has its own codec, a pre-Conway update is stored as its parameter values, and no store holds auxiliary data.

A `RecD` record written as an empty indefinite list `9f ff` is read as the reference reads it: its break passes the reference's check, its fields are read from the items after the break (`ApplyD`, `Coders.hs:499-502`), and every enclosing decoder counts it as one item (#687). `DetachedRecords` walks a block, a body, a witness set, auxiliary data, a whole transaction or a stored output as the reference's decoders read it and lists such records; the read decodes as before and, when that refuses or the input holds an empty indefinite list, decodes again with the records framed as the reference frames them (`Cbor.Detached`), so the parts, the transaction ids and the block body hash span the bytes the reference reads. Only `CborRead.record` and the stored rule take a detached record; a parameter update keeps one as a definite list of its fields' original bytes.

A whole transaction, reached through submission only, is read by `Tx.envelopeParts` for `Tx.fromEnvelope`, the mempool (`MempoolState.parseParts`) and the forger. Before Alonzo it is the `RecD` record `ShelleyTx` (`Shelley/Tx.hs:184-192`): `CborRead.record` takes a definite list of three or the detached record and refuses a non-empty indefinite list with `IndefiniteLength` (#688). From Alonzo it is `decodeRecordNamed "AlonzoTx"` (`Alonzo/Tx.hs:532-553`), definite or indefinite: the third item is the validity flag when it is a boolean, the list then holding four items, and otherwise the auxiliary data of a valid transaction of three (#699); `TxSubmission2.bodyId` takes the same members. The mempool holds and relays a transaction as the reference relays it, `Tx.envelope`: `toCBORForMempoolSubmission` (`Alonzo/Tx.hs:489-513`), a definite list of four with the flag written and the other parts' original bytes, however it was submitted.

## Evidence

`RecdRecordsReferenceSuite`: 118 original encodings (`fixtures/reference/recd-records/cases.jsonl`, oracle `scripts/oracle/conway-decoding/recd_cases.py`), each record definite and indefinite in every era that reads it from a block, the redeemer's units at and over their bounds and the action index at and over its bound. 46 accepted, 72 refused, each refusal recorded with the fragment of the reference failure. Each record is also refused in the reference's order, before its fields: an indefinite list with a field of the wrong type at its break, and a definite list of three at its size. The value is in an output of two and of three items, a map output and a collateral return; the auxiliary data in a whole transaction of each era (the harness gained the transaction decoders of Allegra to Babbage for this). The suite also reads each output whose value a body refuses with the stored rule, which keeps its bytes and gives the value of the definite list, and `StoredChunkedOutputSuite` reads such an output back from the UTxO store while a Mary-to-Conway body that holds it is refused.

`DetachedRecordsReferenceSuite`: 183 original encodings (`fixtures/reference/recd-detached/cases.jsonl`, oracle `scripts/oracle/conway-decoding/detached_cases.py`) of each record written as `9f ff` with its fields after it, in bodies, witness sets, auxiliary data, whole transactions and block bodies of every era from Shelley to Conway, with the refusals around them; 137 accepted, 46 refused, and for each accepted body, transaction and block body the transaction ids and block body hash the reference hashes. Without the second read 131 of the accepted cases are refused. `DetachedRecordsSuite` covers the walk (its refusals, a 200,000-deep input on a small stack), the readers of a detached record, a stored output read again and a parameter update kept; `CborDetachedSuite` the decode.

`TxEnvelopeReferenceSuite`: 91 original encodings of a whole transaction (`fixtures/reference/tx-envelope/cases.jsonl`, oracle `scripts/oracle/conway-decoding/tx_envelope_cases.py`) of every era from Shelley to Conway, 43 accepted and 48 refused: before Alonzo the definite, non-empty indefinite and detached record and the wrong counts; from Alonzo four items with the flag and three without, definite and indefinite, with each form of auxiliary data, and the refusals (a boolean third item with nothing after it, a non-boolean third of four, the wrong counts, heads that disagree with the items, a detached envelope). For each accepted one the harness records the transaction id and the transaction's `encCBOR`, the bytes the reference relays; `Tx.envelope` of the parts read gives them from Alonzo. `TxEnvelopeSubmissionSuite` runs the Conway lines through the mempool's reading; `MempoolInterventionSuite` admits a recorded Plutus transaction without its flag and in an indefinite list, holds it valid (or, from a peer, invalid when its script fails), relays the definite list of four and gives the forger its parts; `TxSubmission2Suite` covers `bodyId`.

## Explicitly unchecked or unconfirmed

Babbage's and Conway's block headers are `RecD` records too, and their KES signature is over the re-encoded header body; the detached and indefinite forms of a header are not read as the reference reads them ([#698](https://github.com/KD5UJC-XYZ/scarab/issues/698)). Node-to-client queries that carry a record are read as trees ([#700](https://github.com/KD5UJC-XYZ/scarab/issues/700)). The node-to-node transaction submission protocol checks a transaction as one item of a tree before the mempool reads it, so it refuses one with a detached record and cuts its id short ([#702](https://github.com/KD5UJC-XYZ/scarab/issues/702)).
