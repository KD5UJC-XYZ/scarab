# Ledger: Conway

Part of the [compatibility matrix](../compatibility.md); the register entry is `ledger-conway` in [compatibility.json](../data/compatibility.json). The three sections below are the cells of the former matrix row, unchanged.

## Status as recorded

implemented incl. scripts, all certificates, treasury donation, the protocol-11 pool rule (VRF key-hash uniqueness); BBODY in the reference's order: the reference scripts of the block, the body, LEDGERS, then the execution units of the whole block (`Conway/Rules/Bbody.hs:268,314`, `Alonzo/Rules/Bbody.hs:149-167,186-214`, #412)

## Evidence

The node applies Conway blocks with the era rules (`ConwayBlockRun`, #85), as the reference applies them (`applyBlockEither` with `ValidateAll`, cardano-ledger f649f975 `Shelley/API/Validation.hs`): BBODY on the era types, a refused block's failures every one the rules record (#412). Their state and phase-2 counters equal the flat rules' on every Conway block of the recorded preprod window (`ConwayBodiesReplaySuite`, which asserts it); `SessionFailureSuite` pins how the follower routes each outcome, a refusal recorded before a defect of the node refused as the reference refuses it. The design's [as-built entry](../design/era-typed-transactions.md#6-results) has the detail.

unit/property; devnet soak (24/24, 41/41 and, with the extended governance load, 44/44) and e2e (Conway 30 comparisons, matched); Preview sync from epoch 646 (Conway, protocols 9 to 11); protocol-11 rules checked against the reference's refusals: 5 taken-VRF registrations refused with `VRFKeyHashAlreadyRegistered` and 5 around them accepted, a reference input that is also an input refused with `BabbageNonDisjointRefInputs` at 10, accepted without scripts at 11 and refused for a Plutus V3 script with `CollectErrors (BadTranslation ReferenceInputsNotDisjointFromInputs)`; the refused bytes replay through our rules (`DevnetRefusedTxSuite`)

`ValueNotConservedUTxO` counts minted tokens as consumed and burned ones as produced, as the reference does (`getConsumedMaryValue` and `burnedMultiAssets`, cardano-ledger f649f975 `Mary/UTxO.hs:72-97`; #828, `ValueConservationSuite`). The verdict was already the reference's; the failure's payload now is too.

The script integrity hash uses Conway's empty redeemers map even at protocol version 8 (#880, `EraNotVersionUtxowSuite`, through Conway LEDGER): absent redeemers are memoized at the era's `eraProtVerLow` (`Alonzo/TxWits.hs:157-162,203-211,227-230`, `MemoBytes/Internal.hs:294-295`, cardano-ledger f649f975). `ScriptIntegritySuite` checks unchanged preimage bytes at Conway's usual versions; `PreviewEmptyRedeemersSuite` checks real Preview transaction hashes by their block era, independently of the protocol version supplied to the rule. The version-11 mismatch failure remains a version test (`Alonzo/Rules/Utxow.hs:282-286`).

UTXOW's `MissingRedeemers` lists the purposes in the order of Conway's `getScriptsNeeded`: spending, withdrawing, certifying, minting, voting, proposing (`Conway/UTxO.hs:62-80`, `extSymmetricDifference` at `Alonzo/Rules/Utxow.hs:378-383`, cardano-ledger f649f975), where it used to list minting before certifying and withdrawing; the verdict is unchanged, and the LocalTxSubmission refusal bytes follow that order (`CertificateRedeemerIndexSuite`; `MissingRedeemersRefusalSuite`, whose bytes are derived by hand from the reference's encoders; `RedeemerIndexReferenceSuite`, the reference node 11.1.3's refusal of such a transaction at protocol 9, byte for byte). Each certificate keeps its own redeemer index: the reference refused two delegations to two pools with a redeemer at index 0 only, missing the second's, and accepted them with redeemers at 0 and 1 (`RedeemerIndexReferenceSuite`); a Conway body cannot repeat a certificate, since `decodeOSet` refuses a duplicate at every version (`libs/cardano-data/src/Data/OSet/Strict.hs:109-110`). The eras before Conway are in [Ledger: Alonzo and Babbage](ledger-alonzo-babbage.md).

Conway's BBODY limits the reference scripts of the block whatever the protocol version (`validateBodyRefScriptsSizeTooBig`, `Conway/Rules/Bbody.hs:314,330-355`; #882, `BbodySuite` at versions 7 and 8), and Conway's LEDGER skips `validateWithdrawalsDelegated` only in the bootstrap phase, protocol version 9 (`hardforkConwayBootstrapPhase`, `Conway/Era.hs:257-258`, `Conway/Rules/Ledger.hs:379-380`; #885, `ConwayRulesSuite` at version 8). A chain that starts Conway by `TestConwayHardForkAtEpoch` keeps the version of Babbage.

HARDFORK counts the pools' VRF key hashes at every change of protocol version whose new major version is 11, a new minor version included (`Conway/Rules/Epoch.hs:367-371`, `Conway/Rules/HardFork.hs:77-78`, cardano-ledger f649f975), as the selected reference build does. Under `11.1` (f649f975 `HardFork.hs:107-125`) it adds one count for each registered pool and each waiting re-registration to the map it has, so after a second change of version at 11 a pool that retires leaves its key hash counted once, and POOL refuses a new registration with it (`VRFKeyHashAlreadyRegistered`). Under `11.2` (cardano-ledger 29a7d656 `State/CertState.hs:525-535`) and the Leios build (9df9f98c, 528-538) it recomputes the counts from nothing, counting a waiting re-registration only where its key hash differs from its pool's, and the key is free once the pool is reaped. `ConwayGovernanceSuite` runs both builds through a minor version change at 11, a retirement and the registration of the retired key; `ConwayLedgerSuite` and `DijkstraTranslationSuite` check each count. The state that `11.1` refuses where it is restored or imported, below 11 with a map that is not empty, is described in [snapshots.md](../running/snapshots.md#unreachable-ledger-state). `StateAdmissionSuite` refuses such a snapshot, written as V10 or migrated from V5, and restores a clean one, which enters 11 with one count for each pool; `LedgerSnapshotImportSuite` refuses the reference-state import and the SCLS import, nothing published; `ConwayGovernanceSuite` enters 11 from 10 from both maps in every build.

The slot of no return (`getTheSlotOfNoReturn`, cardano-ledger f649f975 `Slot.hs:106-114`), which TICK's solidifying of the future parameters uses, is computed exactly (`EpochGeometrySuite`). The reference's `Word64` doubling of the stability window wraps for a window of 2^63 slots or more, which Scarab does not reproduce (#825): an approved deviation ([owner decision](https://github.com/KD5UJC-XYZ/scarab/issues/474#issuecomment-6747536849)).

Script-context translation follows the ledger era carried through UTXOS (#883), including Conway's
V1 reference inputs and reference-script outputs, its exclusive upper bound without a lower bound,
and each certificate's own purpose pointer (`Conway/TxInfo.hs:315-320,399-411,790-803`,
`Conway/UTxO.hs:62-80`, cardano-ledger f649f975). `ScriptContextEraSuite` covers Conway at version 8
and Babbage at version 9; `ScriptContextUsualVersionSuite` checks complete unchanged TxInfo CBOR at
usual versions 5 to 12 for every supported V1/V2/V3 translation. Before Alonzo no Plutus context is
built, and Dijkstra's V4 translator is separate.

## Explicitly unchecked or unconfirmed

native pool rules maintain the reference-counted VRF registry, and every change of version at major 11 populates it as the selected build does. Fresh native genesis retains injected pools with an empty registry, as the reference does; under `11.1` a state below 11 restored or imported with a registry that is not empty is refused ([snapshots.md](../running/snapshots.md#unreachable-ledger-state)); other previously written or imported state still needs its own provenance checks ([#129](https://github.com/KD5UJC-XYZ/scarab/issues/129)); Plutus V3 reference-input refusal only replayed in a unit test, not from the refused bytes; see governance row
