# Ledger: Conway UTXO against `babbageUtxoValidation` (audit, #163)

Part of the [compatibility matrix](../compatibility.md); the register entry is `ledger-conway-utxo-babbage-validation` in [compatibility.json](../data/compatibility.json). The sections below record the implementation, evidence and remaining limits.

## Status as recorded

implemented: the rule makes, for every transaction whatever its validity tag, each predicate the reference makes (cardano-ledger f649f975, `Babbage/Rules/Utxo.hs:342-412`, called by `conwayUtxoTransition`): disjoint reference inputs, validity interval, input set, fee and collateral (`feesOK`), every input exists (spent, collateral and reference inputs), value conserved, outputs too small / too big, bootstrap-address attributes (at most 64 bytes), output network (a bootstrap address has the network its attributes give), withdrawal network, body network, transaction size, execution units, number of collateral inputs; the failure is encoded as the reference does (`ConwayUtxoPredFailure` tag 8 for a withdrawal on another network)

## Evidence

unit: `ConwayUtxoChecksSuite` (eight of the predicates on the era types, #85: each verdict equals the flat predicate's on every transaction of the recorded Conway refusal corpora and on crafted cases for the three they never refuse; the number of collateral inputs is the size of their set narrowed to a `Word16`, as the reference's `fromIntegral` narrows it, checked at 65,536, 65,539 and 65,540 inputs), `ConwayLedgerSuite` (a withdrawal of another network and one of the network, under each validity tag, as a transaction (LEDGER) and as a block (LEDGERS), protocol 10 and 11; the collateral taken only where the rules of UTXO hold; collateral inputs that do not exist or are too many without redeemers; bootstrap-address outputs), `PredicateFailureCborSuite` (the reference's reasons as bytes); devnet `ntc`: the withdrawal case under each validity flag refused as the reference refuses it (raw and text), and a transaction with the flag false whose collateral both nodes take (one input stays)

## Explicitly unchecked or unconfirmed

`validateOutsideForecast` has no counterpart in this rule: after `unsafeLinearExtendEpochInfo` the conversion fails only where the current slot is past the era history it extends (cardano-base 060819b5 `cardano-slotting/src/Cardano/Slotting/EpochInfo/Extend.hs:20-22, 54-66`). The reference never reaches that case: the mempool judges at the slot after its tip, and a block's header is validated only below the tip plus one plus the stability window (ouroboros-consensus 82ecba32 `Shelley/Ledger/SupportsProtocol.hs:100-127`), while the history the ledger gets runs at least that far: its safe zone is the stability window (`Shelley/Ledger/Ledger.hs:171-185`), applied from the tip plus one when the era's end is unknown and from the next era's start when it is known (`reconstructSummary`, `HardFork/Combinator/State/Infra.hs:194-262`). Scarab's header gate waits past the forecast as the reference does, so it applies no such block either. The era-typed `AlonzoUtxo.validateOutsideForecast` mirrors the check; every failing predicate is reported, in the reference's order (#412); Alonzo/Babbage now enforce these collateral and bootstrap-output predicates under #178; Shelley/Allegra/Mary now enforce bootstrap-output bounds and network predicates under #141; protocol-9 set, map and ordered-set uniqueness at decoding is the next row (#327)
