# Ledger: era-specific output forms and body keys, decoder versions 2 to 9 (#379)

Part of the [compatibility matrix](../compatibility.md); the register entry is `ledger-era-output-body-decoding` in [compatibility.json](../data/compatibility.json).

## Status as recorded

implemented: an output is read as the decoder of its era reads it. Shelley, Allegra and Mary: the two-element array alone (`decodeRecordNamed "ShelleyTxOut" (const 2)`, `Shelley/TxOut.hs`); Alonzo adds the three-element datum-hash array (`DecCBOR (AlonzoTxOut era)`, `Alonzo/TxOut.hs`); Babbage and Conway add the map (`decodeBabbageTxOut`, `Babbage/TxOut.hs`), cardano-ledger f649f975; an indefinite array reads like a definite one. Any other shape is the typed `OutputForm(forms, actual)`. A body knows the keys of its era's `boxBody` (Shelley, 0 to 7) or `bodyFields` (Allegra and Mary 0 to 9; Alonzo adds 11 and 13 to 15; Babbage 16 to 18; Conway drops 6 and adds 19 to 22) and refuses the others (`UnknownFields`); Shelley requires the time to live (`MissingField`); Allegra reads key 9 as `()`, which is `null` (`AllegraTxBodyRaw () l`, `decodeNull`), and Mary on read the mint map; a key beyond `Int` is refused as `UnknownKey` and no longer read as its low 32 bits (`Word` keys, `invalidField`, `Coders.hs`), and so is a constructor tag beyond `Int` of a certificate, a credential, a DRep, a voter or a governance action (`decodeRecordSum` and `Summands` read a `Word`: `CborRead.small`), no longer read as the tag of its low 32 bits. Nothing is re-encoded and the original bytes are hashed

## Evidence

`EraFormsReferenceSuite`: original bodies ([counts and source identities](../../fixtures/reference/era-forms/provenance.json), `fixtures/reference/era-forms/cases.jsonl`, oracle `scripts/oracle/conway-decoding/era_forms_cases.py`, harness unchanged): every output form (two, three, one and four elements, map, integer, each also indefinite where an array) as an output and as a collateral return, body keys 3 to 24 and 100, key 9 as `null`, the required keys, a repeated key, keys beyond 32 bits and constructor tags of `2^32 + t` (a certificate and a credential in each era; a DRep, a voter and a governance action in Conway), in each of the six eras, no two cases of an era with one encoding; the counts are in `provenance.json`. Against the decoders before this change 65 refusals of the forms and keys were accepted (measured: Shelley 17, Allegra 16, Mary 16, Alonzo 10, Babbage 5, Conway 1), one acceptance (Allegra key 9 as `null`) was refused, and all 16 tag cases were accepted. The suite also shows that an output in a form its era refuses in a block still reads from its own bytes

## Explicitly unchecked or unconfirmed

an output the UTxO store or the state codec holds, and `TxOut.fromBytes`, read every form, with its map keys as their low 32 bits as earlier builds read them (`TxOut.Forms.Stored`, `FieldKeys.Stored`, ADR 0006; `StoredWideKeyOutputSuite` reads the value such a build stored; the `CodecSuite` fingerprint is unchanged). A block an earlier build accepted with an out-of-era output form or body key no longer replays from the chain store, as the reference would not have accepted it; recovery is an earlier snapshot or a resync. Not covered (the decoder payload alignment of #477): whether the values of a key are the era's (the certificate constructors of each era, the script languages of each era, inline datums as Plutus data, the value of each pre-Conway update field, relays and URLs, network ids and `Word16` indices), duplicate withdrawals before Conway, and the redeemer tag and the cost-model language key, still read as their low 32 bits

Duplicate withdrawals are tracked specifically by [#496](https://github.com/KD5UJC-XYZ/scarab/pull/496). Broader decoder payload alignment remains [#477](https://github.com/KD5UJC-XYZ/scarab/issues/477); this evidence does not establish complete decoder equivalence.
