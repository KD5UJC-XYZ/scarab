# Overflow improvements over the reference (#474)

Part of the [compatibility matrix](../compatibility.md); the register entry is `overflow-improvements` in [compatibility.json](../data/compatibility.json).

## Status as recorded

partial. The owner's standing rule ([#474, 2026-11-09](https://github.com/KD5UJC-XYZ/scarab/issues/474#issuecomment-6747536849), recorded in [decisions](../decisions.md)) is that Scarab never reproduces a wrap, an overflow, an underflow or a narrowing of the reference. A value from outside the node (a block, a transaction, a header, the configuration, a genesis file, a peer, a client, a snapshot or JSON) that the reference would take modulo 2^n gets one of two outcomes instead:

- **refused**: a configuration, genesis or parsing value is refused with a typed problem that names the field and its range, or its arithmetic is exact where the value is used;
- **no verdict**: a value that decides a block's or a transaction's validity, or the ledger state, is computed exactly, or with checked arithmetic; where the exact result does not fit the type the reference uses, the rules report the existing no-verdict outcome (`TickFailure.Vocab`, `LedgerFailure.StateOutOfRange`, `ByronChainError.StateOutOfRange`, `ByronError.StateOutOfRange`, or the `Defect` of the Leios header rules), which withholds the block without blaming the peer and does not stop the node ([decisions](../decisions.md), #573, 2026-11-07).

Below every boundary the results, and every byte written for them, are the reference's. Scarab never reaches a different valid result: where the two differ, Scarab has no verdict, or refuses a configuration the reference would read wrongly. No row is reachable by a mainnet, Preprod or Preview chain or configuration (the arithmetic is in each row); five sites are left as the reference has them, for the reasons their rows give.

Every site in the main sources names its row here (`overflow-improvements.md#<row>` in a comment), and `scripts/check_overflow_register.py` holds the two in step: a wrap idiom in the main sources must name a row, and every row must be named by some source. Upstream citations are cardano-ledger `f649f975`, ouroboros-consensus `82ecba32` (Leios: `2416493b`), ouroboros-network `2fb69829`, cardano-prelude 0.2.2.0, aeson 2.2.5.0, scientific 0.3.8.1 and json-stream 0.4.6.1, as in the [pins](../data/reference-pins.json).

The bound used for "reachable" is the whole supply, 4.5 × 10^16 lovelace, against 2^64 ≈ 1.8 × 10^19, and the slot of a chain, below 2^28 on every public network today and growing by one a second (2^32 slots is 136 years of one-second slots, 2^64 is 5.8 × 10^11 years).

## Fixed elsewhere

- The slot of no return (#825): PR #827 (open) gives the doubled stability window of `getTheSlotOfNoReturn` (`Slot.hs:106-114`) its `Word64` width; `epoch-geometry-windows` refuses every genesis whose doubled window would wrap, so it never does.

- The reference-script sum: the advisory merge `0ecbe4f99` carries the sizes in 64 bits, as the reference's `Int`.

## Evidence

`OverflowConfigSuite` holds each configuration and parsing boundary: at the maximum the value is read, past it refused. The rule suites named in the tables hold each ledger and consensus boundary: below it the reference's result, at and above it no verdict. The reference corpora (`fixtures/reference/byron-genesis-data`, `byron-genesis-balances`, `byron-params`, `coin-arithmetic`, `instant-stake`, `native-json`, `injection-json`, `genesis-pool-fields`, and `fixtures/network/chainsync-pipeline`) are run whole: a case where the reference wrapped is told by the exact value, never by a list of cases.
