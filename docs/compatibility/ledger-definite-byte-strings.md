# Ledger: definite byte strings, decoder versions 2 to 9 (#373)

Part of the [compatibility matrix](../compatibility.md); the register entry is `ledger-definite-byte-strings` in [compatibility.json](../data/compatibility.json). The three sections below are the cells of the former matrix row, unchanged.

## Status as recorded

implemented: below decoder version 12 the reference reads a byte string with `decodeBytes` or `decodeByteArray`, which take a definite-length string only (`ifDecoderVersionAtLeast (natVersion @12)`, cardano-ledger f649f975 `Decoder.hs:350-373, 1426-1448`); every era Scarab reads is below 12, so a transaction body, witness set and auxiliary data of every era from Shelley to Conway refuse an indefinite (chunked) byte string with the typed `IndefiniteLength` of its place: input ids, output addresses, datum hashes, the inline-datum and reference-script wrappers and the script inside, policy ids and asset names, body hashes, certificate, pool, genesis and governance hashes, reward accounts, the extra-entropy nonce of a Shelley to Alonzo parameter update (field 13, read as a `Nonce` at ingress: `Shelley/PParams.hs:463-469`, `BaseTypes.hs:579-595`), vkeys, signatures, bootstrap witnesses, native and Plutus scripts. The readers take the policy as a context parameter (`ByteStrings`) derived from the era's `DecoderVersion` (`ByteStrings.of`); Byron values (header proofs, updates and delegations included) read at version 1 (`byronProtVer`, `Version.hs:162-163`) and refuse a chunked string on that cited source; the oracle measured Byron addresses only. Plutus `Data` (witness datums, redeemer data, the content of an inline datum) and metadata (`decodeMetadatum`, `Metadata.hs:153-222`, the 64-byte bound on the joined string) still read chunked strings. Nothing is re-encoded: the joined value is read and the original bytes are hashed

## Evidence

`DefiniteBytesReferenceSuite`: 444 original encodings (`fixtures/reference/definite-bytes/cases.jsonl`, oracle `scripts/oracle/conway-decoding/definite_bytes_cases.py`, harness unchanged): 206 places across the six eras each as a definite string (accepted) and one chunk (refused), 12 more chunked input ids, 17 chunked `Data` and metadata strings the reference keeps, 3 metadata bound refusals; against the decoders before this change 214 of the first 217 refusals were accepted (measured) and the 4 chunked nonces added after review are accepted too, since `ParamUpdate.read` did not read field 13, and no accepted case was refused; `StoredChunkedOutputSuite`: an output an earlier build stored with a chunked address or datum hash reads back and is written again with its original bytes, while a Babbage or Conway body with it is refused

## Explicitly unchecked or unconfirmed

stored outputs (`UtxoStore`, `UtxoCodecs`, `TxOutMemPack`), re-reads of an output's own bytes, and the application of an update read before keep reading chunked strings (`ByteStrings.Chunked`, ADR 0006). Shelley-based headers and node-to-client query arguments are not measured and keep chunked strings (#437); a block an earlier build accepted with a chunked string in a transaction no longer replays from the chain store, as the reference would not have accepted it: only a node on a network where Scarab accepted such a block can hold one, and it recovers from an earlier snapshot or a resync; text strings (#435), pool relays and the other pre-Conway update values (#436) are read as before; version 12 (Dijkstra) is not decoded
