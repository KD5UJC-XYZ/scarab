# Ledger: definite byte strings in headers and node-to-client query arguments (#437)

Part of the [compatibility matrix](../compatibility.md); the register entry is `ledger-definite-byte-strings-headers-queries` in [compatibility.json](../data/compatibility.json).

## Status as recorded

implemented: two readers outside the transaction decoders that [#373](ledger-definite-byte-strings.md) covered now read a byte string in the form the era's decoder version implies, which is what the reference does. Below decoder version 12 that form is a definite-length string only (`decodeBytes`, `Decoder.hs:350-373`, cardano-ledger f649f975).

- **Block headers.** `HeaderBody` reads its fixed-size fields — the 448-byte KES signature and the VRF certificate's 64-byte output and 80-byte proof — with `decodeFixedSized`, which is `rawDecodeFixedSized =<< decodeBytes` (`Decoder.hs:375-376`), and the header is serialised at the era's lowest protocol version (ouroboros-consensus 82ecba32, `ouroboros-consensus-cardano/src/shelley/Ouroboros/Consensus/Shelley/Ledger/Block.hs:337` — `encodeShelleyHeader = toEraCBOR @era` — and `:346`, `eraDecoder @era` inside `decodeShelleyHeader`) — 2, 3, 4, 5, 7, 9 from Shelley to Conway. `Header.fromRaw` therefore takes `ByteStrings.of(DecoderVersion.of(era))`, and a chunked issuer key, VRF key, previous hash, body hash or KES signature is refused with the header's `IndefiniteLength` (`ChainError.Decode(Header, IndefiniteLength(Header))`, the form the suite asserts). One call site's citation does not stand for five fields: the fixed-size pair uses `decodeFixedSized`, the key and hash fields go through `DecCBOR (VerKeyDSIGN)` (`DecCBOR.hs:472`) and `DecCBOR (Hash h a)` via `DecCBOR ByteString = decodeBytes` (`DecCBOR.hs:353, 492-496`) at the same pin.
- **Node-to-client query arguments.** Consensus decodes the argument with `fromEraCBOR @era` (`Ouroboros.Consensus.Shelley.Ledger.Query`, the `(2, 15)` GetUTxOByTxIn case), which is `eraDecoder @era decCBOR` at the era's *lowest* protocol version (`Cardano/Ledger/Core/Era.hs:236-243`) — again below 12. `NtcQuery` derives the same policy from the era index in the query envelope and reads the `TxIn` argument and its own key, hash and credential bytes under it: a chunked input id is refused through `TxIn`'s own reader (`InvalidTxIn(IndefiniteLength(InputId))`), and a chunked key, hash or credential by this reader's `IndefiniteBytes`.

Both sites derive the policy from the era, so the first era whose lowest version is 12 reads what the reference reads without an edit. `Header`'s two-argument helper forms do keep a fixed policy, for the readers this change does not touch (below).

## As built

- The form test is `Node.isIndefinite`, a property of the item rather than of a reader, so `CborRead.bytes`, `CborRead.text`, the relay name reader and the query readers cannot answer it differently. `CborRead.definite` keeps its stricter Byron meaning (it also refuses a node with no original bytes).
- `Header.bytes`, `Header.optHash` and `Header.vrfCert` gained a policy parameter. Their two-argument forms keep `Chunked` — exactly the policy this file used before #437 — because the Byron header paths and `LeiosBlock` call them, and neither is measured here. Narrowing them would change what the node accepts from the chain in two eras, which is its own change with its own tests: [#574](https://github.com/KD5UJC-XYZ/scarab/issues/574) for Byron, [#570](https://github.com/KD5UJC-XYZ/scarab/issues/570) for Leios.
- The `Chunked` branch of `NtcQuery.bytes` — the half that accepts a chunked string — is unreachable today: every `Era` maps to decoder version 2..9, so `strings(era)` is always `Definite`, and an unknown era index folds to `Definite` too. It exists so the reader answers from the policy rather than a constant, and it is not covered by a test.
- `NtcQuery.Error.IndefiniteBytes` is keyed by a `String` field description, like the cases around it in that enum; typing those field names is owed under [#575](https://github.com/KD5UJC-XYZ/scarab/issues/575) — the #82 and #189 citations this page carried before are both closed issues.

## Evidence

`HeaderByteStringsSuite` samples the byte-string sites a header reads: in the 15-field TPraos layout the KES signature (reached first, since Scarab reads the signature before the body), the previous hash, the issuer key, the VRF key and the body hash; in the 10-field Praos layout the signature and the body hash, which is the only case that reaches `praosTail`'s policy parameter. The VRF certificate fields and the opcert hot key and signature are read under the same policy but are not sampled. `Header.fromRaw` validates no certificate, so a complete body with nulls elsewhere reaches any of them; the body-hash case supplies the VRF certificate pair and body size that precede it. The accepted twin is the fixture corpus: `EraDecodingSuite`'s "announced headers decode from their NtN envelope identically to the block header" decodes committed real headers through the same reader. `NtcQueryByteStringsSuite`: a `GetUTxOByTxIn` argument with a chunked input id is refused with `InvalidTxIn(IndefiniteLength(InputId))`, and a DRep argument with a chunked key hash is refused by the query's own reader with `IndefiniteBytes`. `NtcQuerySuite` holds the accepted queries. Provenance: source-derived from the pinned revisions above — no oracle corpus exists for these two readers, and the issue allows a cited pinned source in place of one.

## Explicitly unchecked or unconfirmed

- A **query argument for an era index this node does not have** falls back to the policy every supported era gives, and the query is answered rather than refused. Whether the reference fails the decode instead is unverified at the pin; tracked in [#587](https://github.com/KD5UJC-XYZ/scarab/issues/587), which also records that resolving it would remove the fallback and the test that pins it.
- **Byron header byte strings** were left accepting a chunked string by this change; [#574](https://github.com/KD5UJC-XYZ/scarab/issues/574) (2026-10-30) reads them at decoder version 1 (`Version.hs:162-163`), definite only, and reads the body proof as a `Proof` (main) or a definite byte string (boundary) through `ByronTransport.bodyProof`; `ByronHeaderBytesSuite` rewrites each field of a real mainnet main and boundary header as one chunk. The rest of the Byron header's grammar (definite arrays, the `Int32` magic, the extra data) is not compared here.
- **Stored blocks with a chunked header no longer replay**: the same recovery caveat as #373, tracked in [#568](https://github.com/KD5UJC-XYZ/scarab/issues/568).
- **Future eras (Leios) are not covered.** Two readers there still match the byte-string value directly and so accept a chunked one: the Peras certificate reader in `LeiosBlock`, and the BLS field reader in `crypto`'s Leios support. Neither can ask the shared form test — the second reads from `Value`, which carries no original bytes — so fixing it is a signature change, not a guard. Leios has no era in `Era` and no pinned reference revision to measure a verdict against yet; tracked in [#570](https://github.com/KD5UJC-XYZ/scarab/issues/570).
