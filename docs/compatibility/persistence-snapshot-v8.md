# Persistence: ledger snapshot format (V8)

Part of the [compatibility matrix](../compatibility.md); the register entry is `persistence-snapshot-v8` in [compatibility.json](../data/compatibility.json).

## Status as recorded

implemented: native V8 (`SCRBSNP8`, #726) is the V7 layout ([V7](persistence-snapshot-v7.md): the V5 body behind a checkpoint binding, with the checksum) whose sidecar keeps each Byron software proposal's installer metadata (`Map SystemTag InstallerHash`) on the registered proposal and on the application version of a confirmed one, as the reference's update-interface state does. The registered V7 → V8 step keeps the binding and the Haskell bytes and rewrites the sidecar from the frozen V5/V7 schema (`SnapshotSidecarV7`) into the current one; V5 files reach V8 through V7. Under the [ADR 0006 amendment of 2026-11-03](../adr/0006-versioned-formats-migrate-on-open.md#amendment-2026-11-03-a-state-that-cannot-be-converted-is-refused-726), a V5 or V7 snapshot whose Byron update state already holds a software proposal or an application version, whose metadata it discarded, is refused with `StorageError.ResyncRequired` by the preflight, the migration run and each step, before any store opens or any file is rewritten; one that holds neither migrates. Nothing is invented for the lost metadata.

## Evidence

`fixtures/snapshot-v8` holds the registered conversions of the 17 `fixtures/snapshot-v7` files, each differing from its source only in the magic and the sidecar's schema fingerprint; `SnapshotGoldenSuite` re-derives every one byte for byte, checks the binding, sidecar and Haskell bytes against the source, and migrates the V5, V7 and V8 goldens once to the same V8 bytes. `CodecSuite` pins the V8 sidecar fingerprint and the unchanged V5/V7 one. `SnapshotV8MigrationSuite`: the frozen V7 writer reproduces a V7 fixture's bytes; a V7 Byron snapshot without software proposals or application versions migrates to the V8 fixture's bytes; V5 and V7 Byron snapshots holding a software proposal, an application version or both are refused at the preflight, the run and the step, with both files of the directory unchanged; the V5 and V7 readers refuse and invent nothing; V8 keeps the metadata through its writer and reader. `SnapshotPreflightSuite`: such a V7 snapshot is refused by `ChainStorage.open` before any recovery or backing reset, and `Main` exits 1 before its RocksDB backing exists.

## Explicitly unchecked or unconfirmed

No real snapshot holding a Byron software proposal is in the repository: the refusal is tested on fixture states with proposals added, written by the frozen V7 writer. Operational databases taken mid-Byron are regenerated by a later resync (#25), not converted. Preprod/mainnet writer upgrades remain #129 and #37/#115.
