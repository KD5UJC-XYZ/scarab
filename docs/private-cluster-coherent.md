# Fresh-genesis coherent reference fixture

`scripts/private_cluster_coherent.py --fixture-profile
conway-pv9-empty-byron-allocations-coherent-v1` is an explicit new private network
profile. It leaves all existing launcher defaults and retained captures intact.
Before any node database exists, it preserves original generated Byron, Shelley,
Alonzo and Conway genesis bytes, then empties only Byron `nonAvvmBalances`.
`avvmDistr` must already be empty. The existing PV9.0 setup change remains the
only Shelley change. All effective genesis bytes and SHA256 pins are retained;
file SHA256 is not confused with Byron canonical-JSON genesis hashing.

The pinned [Byron initializer](https://github.com/IntersectMBO/cardano-ledger/blob/f649f9751074d2ab3de033fc3912f29c9862c1f5/eras/byron/ledger/impl/src/Cardano/Chain/UTxO/GenesisUTxO.hs)
constructs its initial UTxO from AVVM and non-AVVM balances. Empty maps are
supported by the map decoder. Shelley allocation and staking injections are
independent: [the pinned transition](https://github.com/IntersectMBO/cardano-ledger/blob/f649f9751074d2ab3de033fc3912f29c9862c1f5/eras/shelley/impl/src/Cardano/Ledger/Shelley/Transition.hs)
uses `extraConfig.initialFunds.data`, `stakeCredentials.data` and
`stakePools.data` with empty legacy fields, rejecting conflicting populated
sources. These complete structures stay intact.
The resulting network has a different genesis identity and supply/reserve
accounting from earlier captures. No claim of the same network is made.

[Pinned node genesis loading](https://github.com/IntersectMBO/cardano-node/blob/938cba990357ae7c4b7f95c8f75dd9d31174bbeb/cardano-node/src/Cardano/Node/Protocol/Byron.hs)
computes the effective canonical genesis hash and checks an optional configured
expected hash. This fixture rejects an unexpected explicit `ByronGenesisHash`
instead of silently retaining a stale hash. Source pins are recorded project
pins; exact compiled dependency equivalence is not newly proven here.

The runner verifies an absent database for each of its three owned nodes before
writing genesis. It queries the complete unfiltered pre-UTxO in JSON and original
CBOR. Every queried JSON address is decoded by the reference CLI, then all six
entries/addresses/amounts must exactly equal the effective Shelley allocations.
The Scala whole-checkpoint profile separately checks the complete original CBOR.
Stable producer-paused tip brackets remain separate non-atomic acquisitions.

The transfer uses only the relay. A pre-only directory contains nine exact pinned
sources for `BranchInput`; no post-state enters candidate construction. The
offline `coherent-branch INPUT ORACLE` command publishes independently before
reading a separate four-source pinned post-state oracle. The v2 coordinator also
composes derived nonce state and compares all five exported nonce fields. It
compares UTxO, fees, complete certificate counters, tip and epoch; checks full-tuple rollback
and reapply at revisions 0→1→2→3; and rejects stale candidates/undo receipts.
The observer runs without network access. Full ledger/consensus validation,
atomic snapshots, epoch/stake derivation and durability remain unclaimed. The
initial nonce snapshot is supplied; its same-epoch successor is derived in v2.

The inherited owned-resource watchdog caps the live run at 540 seconds plus cleanup
within 600 seconds, with 3 CPUs/6 GiB for reference nodes and 1 CPU/1 GiB for Scala. No public
peers, host-network access, real funds or exported signing keys are involved.
The old two-Byron-output capture remains an explicit Unsupported regression.

## Observed bounded acceptance

The first fresh run passed in 226.836 seconds with no remaining owned containers
or networks. Complete pre-state had six outputs totaling 90,000,018,000,000
lovelace, exactly matching the preserved Shelley injection. One original block
advanced block 57/slot 1039 to block 58/slot 1129 within supplied epoch 2. The
transaction spent one input and created two outputs; all five untouched output
spans matched and the fee pot increased by 200,000. The independent coordinator
matched full post UTxO, fees, certificate counters, tip and epoch, then restored
and replayed the complete tuple at revisions 0→1→2→3, rejecting stale operations.
This is one positive bounded reference scenario, not general ledger agreement.
