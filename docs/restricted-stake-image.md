# Restricted stake projection image

`RestrictedStakeImage` is a bounded binary codec and checked reconstruction component. It does not enable validator restart. The existing complete-stake-checkpoint refusal remains unchanged.

The caller must independently authenticate the whole image SHA-256, ledger-image SHA-256, source join, stake-source identity and complete point (slot, block number, header hash). Checksums supplied alongside untrusted bytes are not authentication. The ledger and stake Context must come from separately checked sources; this component does not authenticate acquisition or check the correspondence between an opaque ledger-image digest and a ledger object.

Version 1 binds the checked context and ledger environment IDs, profile, epoch, fees, exact whole UTxO, instantaneous stake, and mark/set/go snapshots with snapshot fees. Accounts, delegations and pool registrations are recovered from the independently supplied Context, not an image-derived Context. Its checked identity binds those fields. Each snapshot encodes the complete active and pool projections, including ratios, owner stake, pool parameters and registered zero-stake pools. Reconstruction re-derives the complete projection using `ConwayStake.fromActive` and requires byte-for-byte equality. An explicit empty sentinel remains distinct from a registered zero-stake pool domain.

Decode yields an Untrusted value. Reconstruction calls the existing `ConwayStake.seed`, which dispatches datum support from the actual checked ledger environment and recomputes instantaneous stake from exact original output spans. The supplied checked ledger must have revision zero. A newly supplied owner controls the result; historical owner identity, state identity and revision are not deserialized. The caller is responsible for providing a fresh owner. No capability can be obtained by decoding bytes alone.

Limits: 3 MiB image and per-image write budget, 1 MiB whole UTxO, 4096 active or instantaneous entries, fixed-width hashes, bounded canonical unsigned integers and length-before-allocation parsing. All trailing bytes reject. Source contexts retain their existing bounds and closed constructors. The supported historical snapshots must be reproducible under the supplied fixed registration context; arbitrary registration changes are unsupported. This component does not restore certificate, nonce, leadership, governance, reward pulser, undo or publication state and does not relax epoch-crossing restrictions.

Tests exercise independent pin and full-point substitutions, truncated and trailing inputs, semantically corrupt but repinned snapshots, checked source/ledger mismatches, zero-stake pool-domain preservation, original datum output retention, fresh-owner rejection of the old owner, and continuation parity through empty checked blocks after an evolved state. These are projection tests, not transaction replay or complete validator recovery evidence.
