# Certified Mithril bootstrap

**Status**: Implemented with completed local integration gates and reference acceptance for [#27](https://github.com/KD5UJC-XYZ/scarab/issues/27), roadmap E1. Uses the accepted [snapshot design](haskell-snapshots.md), including D1–D9. No persisted ledger, immutable-store or V5 format changes.

## Reference and executable boundary

Certificate-chain validation, STM signatures, immutable digests, Merkle proofs and signed-message comparison stay in the official Mithril client. The pin is `769d862dc2d7941192dac9088d1d86df967bf5cc` (library 0.14.33, CLI 0.13.28). The reviewed executable is Linux amd64; [the build script](../../scripts/prepare_mithril_client.py) fixes source, `Cargo.lock`, Rust image digest, paths and patch, then refuses unexpected binary bytes. The expected SHA256 is `43e126e151d6407b258e2ab37399b8fae4fe7e953f4e3f5366fdf133c1f2ca46`.

The [integration patch](../../scripts/mithril-receipt.patch) leaves verification unchanged. It adds the same verified certificate's network, hash, epoch and protocol-message database Merkle root to successful receipts. It also retains the original authenticated `ancillary_manifest.json` after the client's normal verified ancillary-file moves; upstream otherwise deletes this file with its temporary extraction directory (`mithril-client/src/cardano_database_client/download_unpack/download_task.rs:108–111`, `utils/ancillary_verifier.rs:83–99`). Scarab independently verifies that original manifest through the existing snapshot importer.

The client is copied into the owned staging directory while hashing its bytes, checked against the fixed executable digest, made executable and launched without inherited environment or configuration. Both output pipes are drained and retained memory is bounded. Progress diagnostics may be long; the success-receipt stream has a fixed size limit. Timeout or cancellation closes the process resource and terminates its child. Caller error capabilities remain in the joined owner scope ([ADR 0017](../adr/0017-fibers-end-with-values.md)).

## Completion and identity checks

Exit zero alone is insufficient. At the pin, `mithril-client-cli/src/commands/cardano_db/verify.rs:161–170` prints `verify_error` and returns success after an immutable-files verification refusal. Scarab rejects that event and requires exactly one explicit `verified_db_directory` or `db_directory` receipt. Malformed JSON, duplicate object fields, missing/ambiguous receipts, executable changes, redirects outside the owned directory and process failures produce closed typed errors.

The requested artifact is an exact lowercase SHA256 ID; aliases such as `latest` are refused. Scarab derives the actual artifact ID from the verified certificate epoch and protocol-message Merkle root, using upstream `mithril-common/src/entities/cardano_database.rs:82–88`: SHA256 of the eight-byte big-endian epoch followed by the ASCII root. It must equal the requested ID. This prevents an unsigned descriptor from substituting another genuine artifact while lying about its `hash` field.

The verified certificate's metadata network must match the configured network (mainnet, preprod or Preview) and its protocol magic. This is an explicit local policy because roots may be shared between networks. Metadata participates in the certificate hash (`entities/certificate.rs:172–191`, `certificate_metadata.rs:104–120`); the STM signature signs the protocol-message hash. This check does not claim a stronger direct signature over network metadata than the upstream chain-verification contract provides.

Both operations use the complete immutable range, with no `allow-missing`, range, override or verification-cache shortcuts. A real pinned-client test with the genuine certificate/root/digests but a shortened unsigned descriptor beacon (29,089 to zero) is rejected at digest-message verification. An explicit partial proof with the correct descriptor succeeds in the reference client; that is a separate test of partial-proof semantics, never full-bootstrap evidence.

## Trust and publication

The operator supplies two independent trust inputs: a certificate genesis verification key and an ancillary verification key. Mithril certification covers the immutable files through its beacon, not the ledger state or unfinished next immutable trio. The bootstrap command requires ancillary authentication, while the separate generic `import-ledger-snapshot` command retains its explicitly named unauthenticated opt-out. No ancillary signature is presented as a Mithril certificate.

For downloads, the pinned client acquires and extracts archives using its reference downloader and tar implementation. For an existing cache, Scarab copies regular files into an owned private directory first; original cache bytes are never changed. Symlinks, nonregular entries, recursive source/destination overlap, existing destinations and unavailable ownership leases are refused. Read-only canonical overlap checks precede lease acquisition and are repeated under the lease; invalid paths cannot add a lease inode inside the cache. Supported but inconsistent request/configuration network settings have a distinct typed mismatch error. A post-verification filesystem walk checks the materialized tree before import. Official archives omit the unsigned `protocolMagicId` operator file; Scarab supplies it only inside its private source after matching the verified network policy. An existing contradictory file still fails the immutable import's magic check.

The existing immutable importer checks original block/header bytes, links, hashes, indices and complete framing; truncation is refused. The existing ledger importer verifies the separate ancillary signature/digests, state metadata, exact immutable anchor and reconstructed instant stake, then builds the unchanged V5 snapshot and UTxO checkpoint. A diagnostic provenance JSON file declares its initial schema `version: 1` (future consumers must reject unknown versions) and records artifact/certificate IDs, verifier/source pins, configured network, genesis trust-input digest, ancillary manifest/key evidence and ledger anchor. Its `ancillaryFilesMithrilCertified` field is always false.

The fresh database is built under a sibling temporary directory while holding its destination ownership lease. Required scratch cleanup and persistence finish before a final atomic directory rename. Parent-directory sync failure attempts rollback through the typed error channel, preserving the primary error even if cleanup is denied. Scratch cleanup after an earlier failure or cancellation is best effort; a denied rollback can leave a complete owned directory and is reported as failure, never silently accepted. The stable sibling ownership inode is retained, as for other Scarab database users. This coordinates participating Scarab builds, not arbitrary Haskell or older writers.
