## 0. One constraint changes the shape of jump 1

As agreed, jump 1 says the node holds the mirror state, the rules do not change, and the conversion layer is retired. Those three cannot all be true at once. If the flat rules (`ConwayRules`, `PreConwayRules`, `Epoch`) keep running on `node.LedgerState` while the node holds a `NewEpochState[E]`, every block has to do `fromMirror → rules → toMirror`. That costs O(state) per block: `toMirror` derives `psVRFKeyHashes`, `spsDelegators`, `StakePoolSnapShot`, `nesPd` and the instant stake from about 112k accounts, and `fromMirror` re-derives them and checks them. A 3M-block preprod replay would not survive it.

The differential harness of jump 2 also needs the conversion, because it compares the old flat side with the new side through `toMirror`. So the conversion can only be retired at the end of jump 2.

**Recommendation (decision D1):**
- **Jump 1** swaps the edges and the consensus half:
  - NtC answers move to the mirror codec, piece by piece, with no per-query whole-state conversion.
  - The snapshot payload becomes the Haskell bytes plus a sidecar (§2.4).
  - The chain-dependent state becomes the live `consensus/state` types.
  - The pulser `EnactState` is aligned.
  - The flat ledger stays the live ledger payload. The conversion leaves the query path and runs only at snapshot write and read.
- **Jump 2** makes the ledger payload `NewEpochState[E]`, behind the harness. The conversion retires only at its last commit, into a `legacy` module used for V2-snapshot migration and test fixtures.
- **Alternative (b):** in jump 1, swap the field types of the flat `LedgerState` to the mirror records mechanically. That pulls the rule changes forward (the derived fields `spsDelegators`, `numDelegators`, the registry and DRep delegations must then be *maintained*), so it is jump 2 under a different name. Not recommended.

## 2. Cross-cutting design

### 2.1 Target state type (end of jump 2)

```scala
// consensus/state/NodeState.scala (replaces consensus/NodeState.scala)
final case class NodeState(ext: ExtLedgerState, extras: ConsensusExtras)
//   ExtLedgerState = (CardanoLedgerState = Telescope[EraLedgerState], HeaderState)   (S3 types, now live)
//   EraLedgerState = ByronCurrent(ByronState) | InShelleyEra[E](era: ShelleyBasedEra[E], ShelleyLedgerState[E])
//   ConsensusExtras = boot (BootstrapState, LiteLedger), Byron stats, ProtocolExtras(epoch, TPraos prevEpochNonce),
//                     NodeExtras(plutus, utxo bookkeeping, rewardDraft [until J3.5])
```

- `NodeExtras` shrinks to node bookkeeping:
  - `rewardAmounts`, `prevParamsExplicit`, `pulserAbsent`, `snapshots` (pool residue), `poolDistribution`, `params` (`DroppedParams`) and `Residue` go away. The new rules hold Haskell's own fields, so a residue becomes impossible by type.
  - `Utxo.stake`/`ptrStake` move out of `Utxo` into `UTxOState.instantStake: InstantStake[E]`.
  - `UtxoTables` keeps diff, resident, coin, count, stamp and flushed over RocksDB.
- **Era dispatch has exactly one unpack point:** `NodeRules.applyFull` does `case i: EraLedgerState.InShelleyEra[e] => EraRules[e](using i.era)`, the pattern `MirrorAnswers.mirrored` already uses. Below it, all code is `[E <: EraTag](using ShelleyBasedEra[E])` or concrete `Conway`.
  - Era-range checks of the form `pv >= 9` / `>= 7` / `< 5` that Haskell expresses as *era* type classes become witness methods, for example `ShelleyBasedEra.atLeast(SBabbage)`.
  - Checks Haskell expresses as `hardfork*` protocol-version predicates (`pv >= 11` for the VRF and committee rules, pv 10 `updateDRepDelegations`) stay as protocol-version checks.
  - `TxRules.apply`'s `protocolMajor >= 9` becomes a match on the witness. The equivalence (era ↔ major-version range) is checked by the harness on the eras fixture.
- **Era transitions:** `trait Translate[From <: EraTag, To <: EraTag] { def apply(s: NewEpochState[From], g: Globals): NewEpochState[To] }`, with one instance per adjacent pair as in inventory §1.9:
  - Shelley→Allegra: AVVM to reserves, `StashedAVVM` becomes `Unit`.
  - Allegra→Mary: identity.
  - Mary→Alonzo: PParams upgrade from the Alonzo genesis.
  - Alonzo→Babbage: `d`/`extraEntropy` dropped, `coinsPerUTxOWord`→`coinsPerUTxOByte`.
  - Babbage→Conway: today's `Translate.toConway` plus account/instant-stake/cert-state/gov translation and the initial pulser.
  - A tick crossing several eras (the eras fixture does this at epoch 0) folds `SomeEra.next`.
  - The target era comes from `HardForkConfig.eraAt(epoch, major)`.
  - Order as in Haskell's HFC: translate, then the *new* era's NEWEPOCH. Today `Epoch.preConwayBoundary` runs the pre-Conway boundary and translates afterwards, with a pointer special case; the harness settles whether the two orders agree (risk R3).
  - **As built (J2.3):** `rules/Translate.scala` has one function per pair over `NewEpochState[From] -> NewEpochState[To]` (not a type class: the pairs are a closed chain, and `Translate.next(globals, EraNes)` is the single dispatch on the witness), `rules/Hfc.scala` the combinator's tick (`extendToSlot` then `tickOne`): a `tailRecM` over the epochs between the state and the slot, which at each boundary asks the hard-fork configuration for the era of the epoch (`eraAt(epoch, major)`, the major version being that of the parameters the boundary is about to adopt, `nextEpochPParams`, as the ledger's `shelleyTransition` does), translates one era at a time while the state is in an earlier one, runs `NewEpoch` for an epoch no block is in, and `Tick` for the slot's own. The ledger module cannot see `HardForkConfig` (consensus is after it in the graph), so `Hfc.EraAt` is a function. The translations of the parameters are changes of the node's one flat `ProtocolParams` (`Globals.ledger.alonzoCoinsPerUTxOWord` is the Alonzo genesis value the Mary to Alonzo step introduces; the Conway genesis values are `Globals.ledger.conway`). **R3 is settled by data:** the new order (translate, then the new era's boundary) agrees with the old order on the eras fixture at every transition and on the 1,451 Preview epochs; the only difference found is in the old side (the previous parameters of the first Conway epoch, below).
- **Byron:** `ByronRules` and `ByronState` are unchanged. `rules.handover` (`LedgerRules.scala:227`) produces `NewEpochState[Shelley]` (Haskell's `translateLedgerStateByronToShelley`).
  - **As built (J2.3):** `rules/Handover.scala` is `translateToShelleyLedgerStateFromUtxo` (`ByronTranslation.hs:98`): the Byron UTxO (outputs of no lovelace dropped, the redeem outputs stashed in `avvm`), the genesis delegations and parameters of the Shelley genesis (`FromByron`, taken by the harness from the state the old hand-over built), reserves what the outputs leave of the supply, nothing else. The old hand-over (`GenesisState.initial`) is the same on the eras fixture; its extras (the Shelley `initialFunds` and the genesis staking) are not in the reference's translation and are empty in that fixture, so the question whether a chain with them hands over as the old rules have it stays open (a Byron-start chain whose Shelley genesis has staking or funds is not in any fixture).

`ledger/src/main/scala/xyz/kd5ujc/scarab/ledger/rules/` (new package):

  - the capabilities (`Ask[F, Globals]`, `Stateful[F, S]`, `Raise[F, LedgerFailure]`);
  - a `Stateful.focus(lens)` combinator, so CERTS runs on `Stateful[F, CertState[E]]` focused from `LedgerState[E]` by `LedgerState.cert[E]` (Haskell's `embed`);
  - the interpreter `RuleT`.
- One file per rule family, each an algebra `trait X[F[_], E]` with an instance per era family (Shelley..Babbage share one generic implementation; Conway has its own):
  - `Utxo.scala` (UTXO/UTXOS/UTXOW)
  - `Certs.scala` (DELEG/POOL/GOVCERT; registry and `spsDelegators` maintenance)
  - `Gov.scala` (Conway)
  - `Ledger.scala` (LEDGER/LEDGERS)
  - `Tick.scala` (TICK, RUPD, genesis-delegation adoption)
  - `NewEpoch.scala` (NEWEPOCH/EPOCH/SNAP/POOLREAP/MIR, PPUP adoption, Conway ratify/enact through the existing `Ratify.scala`, `Governance.scala` and `ConwayEpoch` functions on the shared governance types)
  - `Rewards.scala` (attributed `RewardSet`)
  - `Translate.scala`
  - **As built (J2.3), the files of `ledger/rules/`:** `Tick`, `NewEpoch` (and `applyRewardUpdate`), `Epoch` (the Shelley rule, and the dispatcher on the witness), `ConwayEpoch` (EPOCH of Conway, `HardFork`, `predictFuturePParams`), `Snap`, `PoolReap`, `Mir`, `Upec` (UPEC with the NEWPP it embeds), `Rupd` (RUPD), `Rewards` (the reward calculation), `ConwayPulser` (the fresh DRep pulser), `StakeDistribution` (`snapShotFromInstantStake`), `EraLedger` (what the rules do to the ledger state of any era, one match on the witness each: the replacement of Haskell's `EraAccounts`/`EraGov`/`EraStake` classes), `Translate`, `Handover`, `Hfc`, `Convert` (the node's plain records to the mirror's checked ones), `TickFailure`. Every rule is an `Sts` run by `RuleT`; the rules over a part of the state run through `Epoch.within` (`Sts.trans` with the lens as the `Embed`): SNAP on `snapshots`, POOLREAP on `PoolreapState` (a lens onto three parts of the epoch state), UPEC on the Shelley governance state (a lens that is the identity before Conway), RUPD on `nesRu`, MIR and EPOCH on the epoch state. The bodies are pure functions of the state wrapped by `Sts.modifyE`: the state is `NewEpochState[E]` and the capabilities are `Ask[F, Globals]`, `Stateful` and `Raise[F, TickFailure]` (a total refusal: the vocabulary types have no failure in Haskell, `compactCoinOrError`, and a state of a real chain never reaches one).
  - `Bbody.scala` (blocks made, ref-script and ex-units block limits, today in `LedgerRules.scala:474-529`)
  - **As built (J2.4), the files of `ledger/rules/`:** `ConwayTx` (`Counted`, `LedgerEnv`, `StAnnTx`, `CertLens`, `Refuse`), `Certs` (CERTS, CERT, DELEG, POOL, GOVCERT; `CertOps`, `Withdrawals`, `Expiry`), `Gov`, `Utxo` (UTXOW, UTXO, UTXOS; `InstantStakeOps`, `Deposits`), `Ledger` (LEDGER, LEDGERS), `Bbody`, `ConwayBlock` (the combinator's tick and BBODY) and `Invariants`. The algebras are objects extending `Sts` (the rules of one era, Conway), not `trait X[F[_], E]` with an instance per era family: J2.5 generalises over the witness where Shelley to Babbage share a rule.
  - **As built (J2.5), the files of `ledger/rules/` for the eras before Conway:** `PreConway` (the evidence that an era is Shelley to Babbage, with the lenses it gives), `ShelleyCerts` (DELEGS, DELPL, DELEG, MIR; POOL is `Pool`), `ShelleyUtxo` (UTXOW, UTXO, PPUP, the pointer stake, the deposits), `ShelleyLedger` (LEDGER, LEDGERS, BBODY) and `EraBlock` (`ConwayBlock` generalised over the witness). Each is an `Sts` that is one instance for the five eras, `def sts[E <: EraTag](using PreConway[E])`, as `Tick.sts[E]` is; the plan's `trait X[F[_], E]` with an instance per family is not built, as for Conway (J2.4).
- Pure helpers (`tierRefScriptFee`, `minUTxO`, `scriptsNeeded`, `collateralChecks`, `Phase2`, `ScriptContexts`) are reused unchanged. They take `TxOut` and `ProtocolParams`, which are unchanged.
- **Interpreter on the hot path:** the reference is `Kleisli[StateT[Either[LedgerFailure, *], S, *], Globals, *]`. If it costs more than 10% of block-apply time against today's `Either` on a Preview epoch (measured with the existing `Compute.timed(stepLabel)`), replace it by a fused `opaque type RuleT[S, A] = (Globals, S) => Either[LedgerFailure, (S, A)]` with hand-written cats-mtl instances. The algebras do not change.
  - **As built (J2.1):** `Sts[Env, S, Sig, Fail]` is Haskell's `STS` class (`Extended.hs:209-268`): `transition[F[_]: Monad](env, signal)(using Ask[F, Globals], Stateful[F, S], Raise[F, Fail]): F[Unit]`. `Embed[S, S0, Fail, Fail0](state: Lens[S0, S], failure)` and `Sts.trans` are `Embed` and `trans` (`Extended.hs:270-286,475`): `Stateful.focus(lens)` and `Raise.contramap(wrap)` hand a sub-rule its part of the state and wrap its failures. `Sts.check` is `?!`. The interpreter is `RuleT[Fail, S, A]`, a **trampolined** program (data walked by a loop with an explicit typed stack of frames; instances `Monad`, `Local[_, Globals]`, `Stateful`, `Handle`, laws checked with cats-mtl-laws): stack-safe for any length of sequence (owner requirement; tested with 300,000 steps on a 256 KiB thread), where a first fused-function form overflowed. Nothing was ported to measure against, and the algebras do not change with the interpreter, so J2.4 measures the reference stack and a fused form against it on a Preview epoch. Haskell's events (`tellEvent`) are not modelled; the `Tell` capability comes with the first rule that needs it. `Globals(ledger: LedgerGlobals, geometry: EpochGeometry)` pairs the two records rather than copying their fields (`BaseTypes.hs:761-789`).
- **Mempool and forger:** both are Conway-only today (`Rejection.WrongEra`, `ForgeError.UnsupportedProtocol`). They become `MempoolState(base, current: LedgerState[Conway], …)` and `BlockBuilder.select(ticked: NewEpochState[Conway], …)`, and the era is refused at the unpack point by the witness.
- **Header-first validation:** `HeaderRules[S, P]` is already generic. `NodeHeaderRules` builds its `LedgerView` from `nesPd`, the governance-state parameters and `genDelegs`; the forecast stays within 3k/f.

### 2.3 Performance and memory
- **Dispatch:** one witness match per block. Generic code matches on enum ordinals, which costs nothing measurable.
- **Maps:** the real cost is `SortedMap` (byte-wise `Order` on `Credential[R]`) against the HashMap/CHAMP of today. Lookups are O(log n) with byte comparisons, and SNAP builds `ActiveStake` sorted (O(n log n); preprod about 200k accounts, mainnet about 1.3M).
- **Gate per jump:**
  - Preview replay wall time within +15%;
  - `epochBoundary` p99 within +25%;
  - `--memory-report-seconds` peak heap within +20%;
  - `VolatileChain` keeps k states, and persistent trees share structure as today.
- **Fallback (an improvement with a documented reason):** hash maps live, with a sorted view only at encode time. Taken only if the gate fails.

### 2.4 Persisted format (#83)
- **Mechanism fix first (J1.2):**
  - The snapshot (`CSLSNAP1 | u32 2 | fingerprint | payload | sha256`, `LedgerSnapshots.scala:43-120`, with its own `FormatVersion = 2` integer) is not a `FileKind`. Add `FileKind.SnapshotFile` (families `CSLSNAP`, `SCRBSNP`) and `FormatVersion.V3`.
  - `Migrate` steps *every* kind through each shared version, so a V3 bump would rewrite all 29k index files for nothing. Add `FileKind.current: FormatVersion` (the newest version at which the kind's layout changed) and make `Migrate` compare with it; `IndexFile`/`FormatFile`/`IdentityFile` stay at V2.
- **V3 layout (J1.3):** `SCRBSNP3 | sidecar length | sidecar | Haskell state bytes | sha256`.
  - The sidecar is `SnapshotSidecar(extras: ConsensusExtras, gaps: Set[Gap])` under `Codec.auto`, with its own fingerprint golden.
  - The Haskell section is `HaskellLedgerFile.encode` of the `ExtLedgerState` (S8 codec, byte-proven).
  - `Codec.auto` cannot carry the mirror (no `SortedMap` with a custom `Order`, no opaque types, no match-type fields), which is why the Haskell codec carries it.
  - In Byron the Haskell section is absent; the sidecar holds `ByronState`, because our own Byron state has no original `ByronItem` bytes.
  - The UTxO is `map(0)` and stays in RocksDB under the existing `StateBacking` checkpoints.
- **V2→V3 migration (J1.4):** a `SnapshotMigration[F]` in `storage` with `Ask[F, ConsensusMirrorEnv]`. It decodes V2 with `NodeCodecs`, runs `StateMirror.toMirror`, and writes V3 atomically through `AtomicFile`, logged as `formatMigrated`. It runs in `Main` after `NodeSetup` (the environment needs the geometry, forks and Byron parameters). An unknown version refuses the open. No replay.
- **J1.5 (done): V4.** The sidecar embeds the node state and `ConsensusExtras`, so putting the chain-dependent state on the Haskell types changed its shape: `SCRBSNP4`, same layout, new sidecar under a new fingerprint. J1.5 therefore took the version number that the plan reserved for jump 3, which becomes V5. The V2 reader, the V3 sidecar and the node state of their time were frozen in the `legacy` module (D3) *before* the types changed, and `storage` migrates through it: V1 and V2 files (decoded and upgraded, then written as V4), V3 files (the Haskell section decoded and the state written again, read back to check it is equal; the sidecar converted, `gaps` and `observed` carried verbatim: nothing is invented). The live header state is held unplaced (origin tip, zero bounds): the mirror gives it the bounds of `EraHistory` and the anchor.
- **Jump 2:** no format change. At the flip the snapshot is read without conversion, and at J2.9 the flat types and the `to` direction of the conversion move to `legacy` (D3).
- **Jump 3:**
  - V5 when the sidecar shape changes (`rewardDraft` → pulse counter; V4 is J1.5's). Migration V4→V5 maps the sidecar and carries `gaps`.
  - **Migrations never invent data.** A state carries the gaps under which it was written:
    - `NumDelegatorsLowerBound` heals itself after two rotations;
    - `PendingPulsingUpdate` heals at the next RUPD;
    - `NonMyopic` and `VrfKeyHashes` (genesis pools) do not heal; they persist and are reported, and resyncing is the operator's choice, never forced.
  - A node synced from genesis on a jump-3 build has an empty gap set: that is the finish line.

### 2.5 Differential harness (jump 2)
- **Where:**
  - `node/src/main/scala/xyz/kd5ujc/scarab/node/differential/` (temporary, in main sources so the preprod replay can run it):
    - `DifferentialRules[F] extends BlockRules[F, Paired]`, with `Paired(old: legacy.NodeState, neu: NodeState)`;
    - `VolatileChain[Paired]`;
    - `--rules old|new|differential` (closed `RulesMode` in `NodeConfig`).
  - Tests: `DifferentialErasSuite` (eras fixture) and `PreviewDifferentialMain` (from Scala Preview snapshot e, replays epoch e's blocks out of the K1 Scala immutable DB and compares with snapshot e+1).
- **Staging, so a divergence names the rule:**
  - `NodeRules` exposes stages `Tick(epochsCrossed)`, `Header`, `Tx(index, txId)` and `Bbody`.
  - Both sides run stage by stage. After each transaction, compare the *touched* entries (inputs and outputs; credentials, pools, DReps and proposals named by certificates, withdrawals and votes) with the per-entry converters of `LedgerMirror` (made public in the package), plus the scalar pots.
  - After `Tick` and at the sampling points, compare the whole state: `toMirror(old)` against `neu` with a new `Diff[A]` type class over the mirror records, written by hand over the witness like `EraInstances`. It returns the first differing path (`nes.es.ls.cert.dState.accounts[<cred>].balance`).
  - Verdicts are compared too: both `Right`, or the same `BlockFailure`/`PredicateFailure`.
- **Gap-aware relations:** `Relation = Exact | NewRefines | Ignored` per `Gap`/`Derived`:
  - `numDelegators` of set/go: new ≥ old;
  - reward attribution: equal per-credential sums;
  - era-lacking parameters: ignored.
  - This lets the Haskell-shaped rules be *more exact* in jump 2 without failing the harness.
- **Reporting:**
  - Closed `Divergence = StateDiffers(block, era, stage, path, old, new) | VerdictDiffers(block, stage, old, new) | Unconvertible(block, StateMirrorError) | NotPorted(era, stage)`.
  - JSON log event `rulesDiverged`, plus a *repro bundle* (pre-state as V3, block bytes, stage), which `DifferentialReplayMain` reruns in seconds. Small bundles are committed under `fixtures/differential/` as regression tests.
  - Policy: `halt`, or `reseed` (adopt the old side, re-seed the new side with `toMirror(old)`, continue).
  - `NotPorted` reseeds and counts, so the harness is on from the first port and its coverage report shows what is left.
- **Removal:** at J2.9 the flag, the package, the `legacy.NodeState` pairing and `MirrorCheck` go. `follow --mirror-check` becomes `--snapshot-check` (V3 encode, decode, `Eq` at each boundary), and `devnet.py soak --mirror-check` is renamed with it.

**As built (J2.2), where it differs from the above:**
- **The pair.** `Paired(old: NodeState, neu: Option[MirrorState], at: Option[BlockRef])`. `legacy.NodeState` is the frozen V1-V3 schema, not the live old side (stale since J1.5), and there is no `NodeState(ext, extras)` yet, so the new side is the mirror. `neu` is the new side's state *after* the block when it has one: a side that is not ported holds none (keeping a seeded copy nobody reads would double the memory of the run, R6), and is seeded from the old state when it is next needed.
- **Not `VolatileChain[Paired]`.** That retypes every consumer of the chain (forger, mempool, query source, storage, header gate, relay) for a harness that goes at J2.9. `Shadowed` makes `DifferentialRules` the node's own `BlockRules[F, NodeState]` and keeps the new side's state by block hash, found through the header's parent hash; a rollback or a fork needs nothing, and what is older than 2k blocks is forgotten. The suites and the Preview tool use `Paired` directly.
- **Sampling.** `Sampling.Boundaries(2160)` (D7): the first block the harness sees, the first block of every epoch and era, every 2,160th block; `EveryBlock` for the eras fixture. A conversion of a Preview state costs about a second (R7), so a per-block "reseed" is not an option on a real chain; verdicts are compared at every block.
- **Stages.** One, `Stage.Block`. `Tick`, `Header`, `Tx` and `Bbody` need the old side to expose them, and only a ported rule has a state of its own to compare there: J2.3 splits `NodeRules.applyFull` for `Tick`.
  - **As built (J2.3): `Stage.Tick(epochsCrossed)`.** `NodeRules.tick` (the old side's `enterShelley` and `tickLedger`, shared with `applyFull`) answers `OldTick(entered, ticked, epochsCrossed, config, globals)`; `NewRules.tick(era)` is the new side's port, a function of `TickInput(from, header, globals, eraAt)` to `Ticked(EraNes)` or `Refused(TickFailure)` (a tick-only port answers with the state of its stage, which `NewRules.Apply`, a whole block, cannot). `TickStage` runs both and compares at the ticks that do something (an epoch boundary or a hand-over, the start of the reward update, genesis delegations adopted) and at the sampling points: the new side is run from the mirror of the state before the block (`LedgerMirror.to`, the reward update attributed to a placeholder pool by `Relations.seed`) and the old side's ticked ledger is converted the same way, the geometry being the resolved one of the tick. Only the `NewEpochState` is compared: the node extras are the old side's bookkeeping, which the design drops with the old rules, and the telescope and the header state are not what a tick changes. A divergence names the path (`StateDiffers(block, era, Tick(n), path)`) and keeps the repro bundle; `DifferentialReplayMain` reruns it. The stage costs two conversions of a whole state (R7), so it is not taken at every block of a real chain.
  - **`Relation` as built: `Relations`.** The enum of the plan is a set of normalisers applied to the old and the new side's state before `Diff`, each for a place where the Haskell-shaped rules are more exact than the flat ones, with its reason in the code and in the table below.
- **`Relation` (`Exact | NewRefines | Ignored`) is not built**: nothing is ported, so nothing needs a gap-aware comparison. It arrives with the first port that does (J2.3: `Relations`, below).
- **Policy** (`Halt | Reseed`, `--on-divergence`) is carried by `Raise[F, Divergence]` for the halt (exit status 3, event `rulesHalted`); `--repro-dir` defaults to `<db>/differential`.
- **Repro bundle** (`Repro.scala`; the plan said V3): `pre.snapshot` is a format-4 snapshot of the state before the block with the UTxO set as its handle, `utxo.bin` the entries the block reads (state and store), `block.cbor`, `divergence.json` (`kind`, `path`, both values, block, era, stage). `DifferentialReplayMain <bundle> (--genesis-dir|--config)` reruns it; exit 1 means still diverging, the bisect predicate. `NewRules.current` is the one place the ports register. Small bundles go under `fixtures/differential/` when there is one to commit (none exists while nothing is ported).
- **`PreviewDifferentialMain`** replays from the K1 snapshot of epoch e the blocks up to the snapshot of e+1 (read from the ImmutableDB files without opening it) on a scratch copy of the UTxO checkpoint of e, with and without the harness, and compares the end state with the snapshot. **As built (J2.4), where it differs from the above:**

  - *Cost.* A new-side epoch boundary of a 112,000-account state takes about 1.1 s (SNAP 0.4 to 0.55 s of it, EPOCH with the pulser 0.85 s, `applyRewardUpdate` 0.25 s) and the reward update at the start of the rewards 1.1 s, against about 0.1 to 0.4 s for the old rules' whole boundary; the time is in `SortedMap` construction and lookups (`Bytes.compareTo` is a fifth of the profile) and the rewards' rational arithmetic. The plan's gates (design 2.3: `epochBoundary` p99 within 25% of today's, replay within 15%) apply at the flip (J2.8); if they fail, the first measures are building the sorted maps from sorted input (the accounts are in order already), not rebuilding the active stake and the reward set, and the plan's fallback of hash maps with a sorted view at encode time.
  - *Open.* The non-myopic data (`updateNonMyopic`, `Gap.NonMyopic`) is untouched (J3.6); the VRF key hashes are not tracked before the hard fork into 11 (J3.3), and the harness does not compare them at version 10 where the old mirror derives them and the reference has none; `Pulsing` reward updates read from a Haskell state are refused (`TickFailure.PulsingRewardUpdate`, J3.5).
- **J2.5 (Shelley..Babbage LEDGER), from J2.4:**
  - *What to reuse.* The predicates of UTXO and UTXOW in `PreConwayRules` already take the parameters, the UTxO set and the counters (the pre-Conway `apply` is still on the flat state and calls the same functions through the old signatures), so a generic UTXOW/UTXO over the witness is the sequence of calls `Utxow.witnesses` and `Utxo.validate` make with the era's deposits and without the Conway-only checks (reference inputs, collateral from Alonzo, `ValidationTagMismatch`, the reference-script fee, `WdrlNotDelegatedToDRep`, treasury value). `StAnnTx`, `Counted`, `Refuse`, `CertLens` (Conway's; the Shelley certificate state needs its own), `InstantStakeOps` (the credential stake; Shelley's `ShelleyInstantStake` adds the pointer stake, `Shelley/State/Stake.hs`, which the delegation by pointer resolves through `ShelleyAccounts.ptrs`) and `Deposits` are the places to generalise.
  - *The Conway-only choices to undo.* `Bbody` counts every block for its issuer (`incrBlocks False`: Conway has no overlay); before Babbage with `d > 0` a block made in an overlay slot is not counted, which the old rules take from the leader check's result (`LeaderCheck.Overlay`), so the signal needs it (or `isOverlaySlot` from the slot and `d`). BBODY has no reference-script limit before Babbage and no execution-unit limit before Alonzo. `ConwayBlock` takes the state through `Hfc.tick` and then matches the witness once (`SConway`); the rest of the era-generic code is `body` and `NewRules.withConway`, to generalise by the witness (the mirror is rebuilt with the tip, the new-epoch state and the counters, in the era of the telescope's current state). The block of an era whose pre-state is of the one before is `NotPorted` for the same reason as the first block of Conway (the telescope is not extended).
  - *The pre-Conway rules that have no Conway counterpart to start from:* MIR certificates and genesis delegation (`PreConwayCerts`), the pointer of a registration (`Ptr(slot, txIx, certIx)`, from the slot of the block, `LedgerEnv.txIx` and the certificate's index), PPUP (`PpupRules`: the proposals of the genesis delegates, current or for the next epoch by the slot against `firstSlotNextEpoch` and the stability window, adopted at the boundary), withdrawals paid one by one in DELEGS (`WithdrawalsNotInRewardsDELEGS`), `ExpiredUTxO` before Allegra.
  - *The harness.* `Relations` is where the old mirror cannot say what the new state does (the delegator counts of a carried state are the entry J2.4 added); the new side verifies the signatures and decodes the block itself, so per-block times compare the old side's whole block with the new side's ledger part. `PoolMedataHashTooBig` (`Pool.hs:245`) is in neither rule set.
- **J2.6 (rule suites run on both sides), from J2.5 (done: §4 item 5):**
  - *What exists.* `ShelleyLedgerSuite` (LEDGER of the five eras against `TxRules`, transaction by transaction: `Case[E]` pairs a protocol version with the witness and the evidence, `both`/`agree` compare the rule that refuses or the state converted back through `LedgerMirror.normalised`, and `afterOf` gives the new side's state for inspection), `ShelleyBbodySuite`, `ConwayLedgerSuite`, `BbodySuite`.
