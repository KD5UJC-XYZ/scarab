# Conway PV9 required payment-key coverage

Milestone 0.6.0 adds a pure, bounded `MissingVKeyWitnessesUTXOW` coverage predicate in `ledger`. It is separate from strict provided-signature verification in `core` and value conservation in `ledger`. None implies complete transaction validity, script validation, or a ledger transition.

## Closed input contract

`Coverage.decode` accepts a four-field Conway envelope with body fields exactly 0 (spending inputs), 1 (outputs), and 2 (fee); a VKey-only witness map (empty is permitted); `isValid=true`; and null auxiliary data. `Coverage.check` requires explicit Conway / protocol-major 9 context. There is no on-chain era detection from transaction bytes alone.

`Coverage.decodeResolved` reads an address-preserving map from actual `[txid32, uint16 index]` references to complete address/value-only outputs. Legacy two-element outputs and map outputs with exactly fields 0/1 are supported. All supplied output entries, including unspent ones, must fit the closed profile; only actually referenced entries contribute required payment keys. Only Shelley base key-payment/key-stake addresses (kind 0, 57 bytes) and enterprise key-payment addresses (kind 6, 29 bytes), with network nibble 0/1, are admitted. The network nibble is checked for shape, not against a selected chain; staking credentials and newly created output recipients do not become spending requirements.

Every excluded body/witness/output field is rejected by presence, including empty values. Field 14 explicit signers, mint, certificates, withdrawals, collateral, scripts, pointer, Byron, reward and other address kinds return `CoverageError.TypedUnsupported`. Missing body fields, malformed sizes, invalid network nibbles, duplicate semantic map keys/inputs/VKey public keys, and unknown set tags fail parsing. Spending-input and witness sets admit arrays or tag 258. Empty inputs and unresolved input references have distinct prerequisite errors. Empty witnesses parse and yield missing owners. No unresolved input is silently dropped.

`Projection` and `Output` can only be created by the checked decoder. Core immutable `Bytes`, `PublicKey32`, `Signature64`, `VKeyWitness`, `ExactBodyCbor`, and existing ledger `TxIn` are reused; ledger depends on core, never the reverse. Original envelope/body/output bytes are retained. CBOR bounds remain 1 MiB, depth 64, 100,000 items, 1 MiB strings; output references fit uint16. These bounds are research admission policy, not ledger consensus limits.

## Predicate and independent composition

Required = payment hashes of resolved actual spending inputs. Provided = independently parameterized Blake2b-224 of each actual 32-byte raw witness public key. Missing = required minus provided. This hashes neither the CBOR wrapper nor signature, and is not truncated Blake2b-256. Repeated payment owners deduplicate; unrelated provided witnesses do not invalidate coverage. Diagnostics render in deterministic sorted order.

`CoverageResult.required`, `.provided`, `.missing`, and `.covered` describe coverage only. A well-sized off-curve public key still has a hash; signature verification must independently reject it. Modifying only a signature leaves coverage unchanged. An empty witness set is meaningful for this predicate even though the older standalone witness parser deliberately requires at least one signature.

`coverage-demo` checks two byte-pinned archived cases and prints coverage, strict provided-signature results, and balance independently. Its harness match means these particular fixture expectations agree. It does not expose a transaction-validity Boolean. Both cases have valid supplied signatures and conserved value, but the rejected case lacks Alice's required payment key.

## Evidence boundary

The fixture pair is extracted from the pinned Blueprint archive member `eras/conway/impl/dump/Conway/Imp/ShelleyImpSpec/UTXOW/MissingVKeyWitnessesUTXOW`, generated by pinned Haskell ledger tests. Its sequence and parameter context establish archived Conway PV9 evidence despite the suite's Shelley name. The accepted setup transaction creates the rejected transaction's two resolved inputs; their references use the exact original body hash. Applying only the accepted setup reproduces final UTxO addresses and values. This projection check is not a full state transition.

The archive stores accepted/rejected booleans, not a serialized missing-hash failure payload. The generator source explicitly asserts `MissingVKeyWitnessesUTXOW` for Alice; the hash `3c875ce0f647bdcc64b70e62814680fbd939f8faf0203b98236ede7b` is independently reconstructed from raw data, not claimed as a separately stored Haskell diagnostic golden. Original Haskell tests were not rerun.

Target node-11.1.3 ledger source review is a separate evidence class at `f649f9751074d2ab3de033fc3912f29c9862c1f5`: Shelley UTxO required-key extraction, Shelley UTXOW separate signature/coverage predicates, and Conway's Babbage delegation. Public key-hash CLI evidence uses CLI 11.2.3.0 bundled with node 11.1.3; it is a hash oracle, not ledger validation. The pinned research sodium verification evidence checks both supplied signatures without becoming a runtime dependency. Full provenance, immutable pins, original bytes, source assertion and reproduction are under `fixtures/coverage`.

All additional negative/role/ownership/range tests are source-derived or synthetic, not new Haskell corpus outcomes. No productive keys, signing, key generation, external peer, node process, transaction submission, or publication is involved. JVM dependencies are unchanged.
