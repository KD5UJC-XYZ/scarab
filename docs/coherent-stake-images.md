# Coherent stake component image bridge

`CoherentStakeImages.encodeSnapshot` accepts one immutable `CoherentSequence.Snapshot`, created by the runtime from one cell read. It derives both ledger and stake images from that snapshot, cross-checking the ledger environment, certificate full point, acquisition tip, nonce/certificate linkage, stake ledger identity/revision and actual source context. The stake image contains the SHA-256 of the exact ledger image. Both bind the same slot, block number, header hash and externally supplied source identities.

This is a partial component export, not runtime persistence or restore. Reward, epoch and boundary compositions are explicitly refused. Existing ledger image v1 restrictions remain unchanged: the closed Plutus profile, private network magic, epoch zero and slots 1 through 999. Original genesis and parameter bytes must match the actual checked environment; the native diagnostic Context ID must match the source join identity. The manifest hash and source join must still be independently authenticated by the acquisition/controller boundary. Non-atomic reference acquisition does not become atomic merely because runtime export is coherent.

The publication digest commits to both whole image hashes, source metadata, full point and historical coherent/certificate/nonce/eligibility identities. `verify` requires that digest and the expected metadata from an independent trusted channel. It verifies image hashes and their mutual source/point correspondence and returns non-authoritative components. It does not certify fresh acquisition, independently authenticate the caller, or authorize installation. An old immutable snapshot can be exported as historical data after its owner advances; export does not imply current-owner authorization.

Remaining restore prerequisites are explicit: a complete certificate counter/context image with source authority; nonce state and certificate linkage; eligibility context/checked-header correspondence; complete source join authentication; bounded retained original replay and final coherent tuple checks; state and revision rebasing; and a fresh-owner factory with rollback/fence rejection. These component images do not carry undo receipts or those capabilities. The existing `LocalDerivedCheckpoint` stake refusal and durable runtime factories are unchanged. Tests showing a newly constructed runtime rejecting an old fence use existing checked source construction, not image-based restoration.

Tests include public refusal of synthetic reward and boundary compositions and of the ordinary non-Plutus profile. Optional independently pinned retained evidence replays actual checked original blocks, compares pre/post export, rejects mixed image pairs and point/source substitutions, and verifies immutable historical exports. No live cluster or transaction submission is required.
