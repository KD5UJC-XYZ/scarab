# Early clean restart controller stage

`private_cluster_plutus_early_restart.py` is an opt-in importable stage for the existing owned two-service controller. Importing it has no process side effects. It does not replace the existing single-service or two-service entry points and does not launch anything by itself.

`perform_early_restart(controller, live, manifest, store_id=..., session_id=..., generation=..., resume_producer=..., freeze_producer=..., checkpoint_after=1, continuation_builder=None)` requires an already acquired, checked initial packet on a frozen owned mutable reference network. Both `service-1` and `service-2` roles must be unused. The caller retains ownership of the global deadline, watchdog, signal handling, final service cleanup, and reference lifecycle. Producer callbacks must operate only the controller's verified owned processes; resume returns the actual Unix-millisecond timestamp.

The stage starts the first service with checkpoint-after, waits for its checked publication budget and clean finalized process exit, freezes the producer, and requests the reference's existing exact historical acquisition at the checkpoint full point. It independently parses the bounded checkpoint wire envelope and checks its whole-byte digest, complete request claim, configured source/store/session/generation, checked terminal pin, and acquired full point. This is an envelope and authority decision, not an independent implementation of ledger replay. The Scala recovery path remains responsible for original-block validation and exact semantic terminal reconstruction.

Only after those checks does the controller publish `restart-authority.json`, separately from the untrusted service request. The authority file is individually CREATE_NEW; neither it nor the binary/request pair is claimed crash durable. Old process removal precedes restored process creation. Exact read-only checkpoint and authority mounts are inspected with the existing two-service CPU/memory/network/privilege envelope. The service's opt-in readiness now includes `startupAdmission`, an actual guarded service snapshot with full pin, pool size/bytes/eligible count, and closed/rebuilding flags. The adapter requires a new owner, new checkpoint attribution, the exact restored point and depth, and an observed empty pool before resuming the producer.

The returned `RunningRestored` identifies a running service. `wait_checked_successor(controller, restored, seconds=20)` validates the first later checked publication's fresh owner, strict next full point, source and manifest, and preserves its raw hash. It does not terminate the service. A supervisor can therefore continue with its normal work after the early restart instead of exhausting a special one-block continuation helper. This version makes no transaction-before/restart/transaction-after claim and does not submit tested transactions. The exact acquisition proves the reference full point; it is not a new whole-UTxO/fee/stake oracle comparison, and evidence explicitly says `wholeStateOracleCompared: false`.

The default continuation uses the existing epoch-zero service with its unchanged duration and resource limits. `continuation_builder` is a trusted executable supervisor extension, not a verified long-run path or data-driven command input. The adapter checks the resulting owned container resource and mount envelope and readiness contract; it cannot establish arbitrary builder semantics. A separately reviewed multi-epoch runtime and supervisor are required before a 600-second or four-hour claim is meaningful. The current checkpoint itself remains linear epoch zero with at most eight originals, without compaction or historical rollback histories.

The independent controller must make a current anti-rollback decision on every attempt; historical acceptance alone is insufficient if its store/session policy can be revoked. This stage uses fresh roles, fresh output paths and an explicit generation and never automatically reuses an acceptance file. Exceptions leave cleanup to the owning controller's existing finally path. The helper never removes unrelated containers.

`test_private_cluster_plutus_early_restart.py` is offline and uses only synthetic structural wire data. It covers exact identity/source/acquisition mismatch, incomplete and substituted pairs, strict JSON integer types, malformed binary bounds, create-new acceptance, fresh empty pool, checked successor, and the clean-exit/acquire/authorize/remove/restart sequence. These tests do not claim a live process restart or semantic validity for the synthetic image blobs.
