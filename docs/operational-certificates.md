# Operational-certificate signatures (v0.17)

This implements one public-input predicate: did the supplied cold issuer key sign
this operational certificate? It does not establish an authorized issuer, a current
counter, a KES signature, registered pool membership or a valid Cardano header.

## Exact boundary

`lab.opcert.OperationalCertificate` exposes checked private-constructor `UInt64`,
`HotKesKey32` and `Certificate` values. The certificate holds the existing immutable
`Signature64`. Cold keys use the existing checked `PublicKey32`. Convenience
`verify` checks raw input lengths/nulls and unsigned integer range. No unchecked
case-class copy path, private key, signing, proving or generation operation exists.

`signableBytes` produces exactly 48 bytes:

```
rawHotKesKey32 || counter_u64_big_endian || startPeriod_u64_big_endian
```

No CBOR wrapper, header/body hash, domain prefix, network tag, nonce, textual hex
or prehash is included. Both integer fields admit 0 through 2^64-1, including the
upper half not representable as a positive JVM Long. This follows the retained
exact-release ledger `OCertSignable.getSignableRepresentation` source, not an
inferred header serialization rule.

`verifySignature` invokes the existing experimental `StrictEd25519.verifyEd25519`
exactly once on well-formed input. It keeps its pinned sodium-source acceptance
profile, point/scalar checks and arbitrary-message behavior unchanged. No native
runtime or new dependency is added. The return is either typed `Malformed` or
`InternalFailure`, or narrowly named `SignatureRejected` /
`OperationalCertificateSignatureVerified`. Unexpected nonfatal exceptions map to
internal failure; fatal JVM errors propagate. No provider failure becomes a
rejected signature. The injectable primitive seam is package-private for tests.

## Evidence and reproduction

See [fixture provenance](../fixtures/opcert/README.md) for source/license hashes,
probe provenance and native source-build caveats. Four unchanged public archived
headers provide four genuine certificate signatures. All six existing native
mutations per original reject: hot-key bit, counter+1, start+1, both integers
little-endian, signature bit and cold-key bit. The little-endian negative can be
represented by byte-reversed unsigned values passed through the same public API.
No expected signature was generated by the Scala implementation.

Twenty-five independent Python `int.to_bytes(8, 'big')` controls cover the full
cross-product of counter/start values 0, 1, 2^63-1, 2^63 and 2^64-1. Tests also cover
null/length/range errors, immutable input/output ownership, one-call gating,
primitive contract failures, nonfatal/fatal separation and concurrent shared inputs.

The CLI checks the embedded TSV digest before parsing. The projector embeds the
manifest digest, checks its exact file set/source hashes, bounds each file to
64 KiB, then extracts only the retained certificate fields from fixed-size/depth
fixture CBOR. Neither tool is a generic header decoder. The 23 projector negatives
include semantic evidence changes, bounds/corruption and edited-manifest bypass.

## Still gated

The archive's preprod labels are not independent historical chain-authenticity
proof. The native reference is a pinned source self-build, not demonstrated
release-binary equivalence. Finite tests are not a cryptographic security audit or
universal target equivalence. The underlying strict verifier remains experimental.

Historic registered-pool/VRF hashes and opcert counter state remain absent.
Computing those values from these same headers would be circular evidence.
The research record's source-derived KES prototype and period values are not
admitted here. Exact target HeaderBody signable reserialization, full independent
KES oracle coverage, leadership, nonce state, chain continuity, body commitments,
ledger validation, rollback/selection and live relay interoperability remain gated.
