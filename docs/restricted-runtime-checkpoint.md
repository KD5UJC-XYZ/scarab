# Restricted runtime restore by checked replay

This restores a complete `CoherentSequence.Runtime` only within a closed domain: diagnostic Plutus/stake, epoch zero, private network, a linear uncompacted source-anchored history of zero through eight blocks, and no reward or boundary composition. Historical revision must equal retained depth. Prior rollback, discarded history and compacted prefixes reject. It is an early bounded restart prerequisite, not restoration of a long-running compacted service.

Export consumes one immutable snapshot containing both terminal state and retained originals. The checkpoint includes exact header/block bytes, complete ledger/stake component images, certificate/nonce/eligibility terminal identities, full source and terminal points, and historical provenance. A separately retained controller record must authorize the exact whole publication SHA-256 and its store, session, generation, source join and point claim. The controller must enforce its active anti-rollback policy; no default authorizer is supplied. Hash validation alone does not authenticate a source or authorize restoration. AcceptedAuthority records a historical controller decision; recover does not re-query the controller. Callers must reacquire acceptance under the current anti-rollback and revocation policy for each restore attempt when store/session authorization can change.

Recovery also requires a separately checked `NativeLedgerV2.Checked` source acquisition matching the accepted join and full source anchor. Source contexts and stake seeds are re-derived using existing checked APIs. Contiguous exact originals are checked before runtime creation. A private fresh runtime then replays every original using ordinary prepare/publish. Certificate, nonce and eligibility identities, full terminal point, ledger/stake semantic image bytes and coherent linkage must all match before the runtime is returned. Cancellation, timeout, corrupt originals and terminal mismatch return no partial runtime.

Fresh recovery attribution is generated internally from a random UUID bound to the authenticated source and publication. Existing ledger checkpoint and stake-seed constructors create new ledger, stake and coherent identities. Historical IDs are provenance only and are never installed. Repeated restoration of the same authorized checkpoint creates different lineages. Old runtime fences/candidates and raw ledger undo receipts reject; new replay receipts support rollback only as far as the authenticated source anchor. Rebased revision starts at zero and advances once per replayed block; the accepted linear domain means its terminal numeric value equals the historical revision without restoring it.

No pending HTTP envelopes, admission reservations, relay leases, old owners or old undo objects are restored. A subsequent service must construct a new empty volatile admission pool. This API does not manage process crash files, atomically persist a controller record, reconnect a network peer, or authenticate the external acquisition method. Reference acquisition remains non-atomic. Existing LocalDerivedCheckpoint stake refusal and compacted restore paths are unchanged.

Public tests cover malformed inputs and unsupported composition. Independently pinned retained tests exercise real source reconstruction and checked publication replay, distinct restored lineages, old fence/candidate/undo rejection, source rollback floor, controller/source mismatch, invalid originals, cancellation and deadline behavior. No live cluster is required. Compacted-anchor certificate/nonce/eligibility hydration, authenticated longer replay ancestry, multi-epoch restoration and restart of a sustained service remain separate prerequisites.
