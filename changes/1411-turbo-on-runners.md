### Changed (conformance, #1411)

- Follows #1412, which ran `uplc-turbo` on GitHub-hosted runners for its memory counts alone, on the then untested assumption that a shared runner's timings are too noisy to publish. Measured, a runner with a given CPU scores as steadily as a quiet development machine, while runners of different CPUs differ widely, and a runner cannot be chosen by CPU. So `uplc-turbo` is now an ordinary scenario of the **Conformance reports** workflow (input `uplc-turbo`, on by default), in a job of its own, measured and published on one reference CPU (`TURBO_REFERENCE_CPU` in `scripts/conformance/scenarios.py`): on a runner of another CPU the job ends before the build with a `not-reference-cpu` outcome and stays green, to be re-run. `uplc-turbo-any-cpu`, and the nightly run, measure on any CPU; such a report is never published. A failed turbo job no longer fails the run, so the run stays the next nightly CBOR comparison's baseline.
- `publish.py` checks the very bytes it stages: the report and its provenance must hold together (shape, size, hashes, scenario, era, time, commit and CPU) and the report must be valid against the site's schema and readable by its scoring; it refuses a `uplc-turbo` report of another CPU than the reference, wherever it was written, and names each scenario a run asked for without a report, whose `latest/` it leaves as it is.
- A report's provenance records the CPU a tool container sees (its model, the machine's logical CPUs, what `nproc` reports and the cgroup's CPU quota, and why the probe failed when it did) and the container's limits; `run.py` checks its shape before writing it.
- The turbo job's summary gives the score by the site's rule (`summarize.py` writes `turbo-score.md` and `turbo-score.json`): met and total, the programs missed on memory and on CPU alone, each with its CPU time and memory as multiples of its budget, the median and 95th percentile of bytes per memory unit, the CPU and whether the report is publishable, once the report is checked as `publish.py` checks it.

### Removed (conformance, #1411)

- `run.py --allocation-only`, the workflow's `uplc-turbo-memory` input and `scripts/conformance/turbo_memory.py`, added by #1412: the flag only lifted the refusal of `uplc-turbo` on CI, so a memory-only run cost as much as a full one, and the full run's summary includes its memory counts.
