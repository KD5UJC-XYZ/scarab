### Added (era types, #85)

- Conway's MEMPOOL runs on the era types, with the reference's order: a transaction whose inputs are all spent is refused alone, the votes of unelected committee members are refused before protocol version 11, then the ledger rule runs. Its run applies a transaction with every check and keeps what it was validated with; a held transaction is applied again as each build's consensus does: 11.1 annotates it again and skips the static checks, 11.2 and the Leios build reuse its annotation under the same major version and check it in full under another. On every Conway case of the refusal corpus, under each build and at protocol versions 9 to 11, and on the pool suites' transactions, it gives the existing mempool rule's failures in the same order or leaves the same state, but where the 11.2 and Leios builds refuse a withdrawal in the ledger rule below version 11; at the root, its refusals of 81 of the corpus's 84 Conway cases, each under its recorded build, encode to the reference's byte for byte, the three left out (`tx-too-large`, `tx-too-large-spent-inputs` and `utxo-mint-units-too-big`) being those the mempool's measure refuses before the rule. The node still judges with the existing rule, so nothing changes in behaviour.
