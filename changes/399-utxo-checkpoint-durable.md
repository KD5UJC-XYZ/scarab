### Fixed (memory UTxO store, #399)

- The memory UTxO store's checkpoint file `utxo.bin` is now durable (fsync, through `AtomicFile`) before the snapshot that binds it is written. Before, it was not forced to disk, so a crash could leave a snapshot whose checkpoint was torn; the checkpoint digest refused that snapshot at restore and an older one was used. The reference's in-memory backend plays the same part with the tables it writes inside the snapshot directory, covered by the snapshot metadata's checksum (ouroboros-consensus 82ecba32 `Storage/LedgerDB/V2/InMemory.hs` 216-224 and 254-270), without an fsync; forcing the file to disk is an owner-approved deviation, recorded in #474 (2026-10-27).
