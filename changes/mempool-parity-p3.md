### Changed (mempool, admission backpressure)
- **A transaction that finds no room in the mempool waits instead of being refused, as the reference does.** `Mempool.add` releases the state lock and retries from the first measure whenever the pool changes (a transaction added or removed, a new tip), until the transaction is held or refused for another reason. Waiters are served in order through two queues: a peer's transaction takes the remote queue and then the common one, a local client's only the common one, so a local client passes the peers in line, and only the head of the line waits for room. A peer's wait holds back that peer's TxSubmission2 replies and a local client's wait holds back its submission, outside every protocol timeout; a lost peer or a closed client leaves the line. `sync`, `removeTxsEvenIfValid` and `awaitChange` do not wait for a waiting submission. A transaction larger than the whole capacity is still refused at once as "mempool full" (the reference would wait for ever). The log has a new line, `mempoolWaiting`, when a submission first finds no room ([IN-82](docs/implementer-notes.md)).
