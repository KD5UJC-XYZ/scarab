### Fixed (restoring a database of the older snapshot formats, #145)
- **A database whose snapshots are format 1 restores and replays; one the node cannot restore safely is refused with a typed error that says to replay.** The snapshots of format 1 go with the UTxO checkpoints of the builds before K6 (2026-10-14, `e7300826`), whose RocksDB key is `txid ++ u32` (36 bytes) where this build's is `txid ++ u16` (34 bytes, the Haskell node's). K6 bumped the snapshot format to 2 so that such a database would be replayed, and the migration of J1.4 later accepted format 1 again on the argument that the snapshot payload did not change; the checkpoints were not looked at, so a migrated format-1 snapshot was restored over a store in which every output was unreadable, and the first block that spent a stored output failed with `BadInputsUTxO` (the K1 Preview database of 2026-10-14: the first 11 blocks after the anchor applied, the 12th was rejected). `RocksUtxoStore.restore` now reads the keys of the checkpoint and, for the old layout, writes the live store from it under the current keys (2.6 s for the 3.2 million outputs of Preview; the checkpoint itself is not touched, so it can be restored again and an older build is not locked out of it). A checkpoint that holds keys of both layouts (an older build then this one wrote to the same store, so a spent output may still be there), an output index above 65,535, or a key of another length is refused with `StorageError.UtxoCheckpoint(dir, CheckpointProblem)`, whose message says to stop the node, remove `<db>/snapshots` and `<db>/utxo` and start it again (replay from the immutable chunks).
- **Formats 2, 3 and 4 were not affected**: their checkpoints already have the 34-byte keys. `ChainStorageSuite` now opens a database of each of the formats 1 to 4 (snapshot files written by the frozen writers of the `legacy` module, checkpoints in the layout of their time, the live store ahead of the newest snapshot), migrates it, restores the newest snapshot, replays the immutable blocks that follow and compares the state and the UTxO set with a replay without storage; format 4 also with 700 blocks, 15 or more checkpoints and a rollback after the restore. The format-1 case fails without the change with `BadInputsUTxO`. `UtxoCheckpointLayoutSuite` covers the store alone, the refusals included. A real V4 database (the J2.7 Preview sync, 3 snapshots with checkpoints) was opened, migrated, restored and replayed beyond 200,000 blocks with no error.
