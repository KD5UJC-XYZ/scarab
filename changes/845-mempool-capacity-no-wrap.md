### Changed (mempool, #845)

- **`MempoolCapacityBytesOverride` and `--mempool-bytes` take a `Word32`, from 0 to 4,294,967,295, as cardano-node 11.1.3 reads the configuration.** A configuration file therefore means the same to both nodes. 0 is now accepted and gives one block. A larger number is refused with a configuration error that names the value.
- **Scarab does not wrap the mempool's capacity where the reference does ([approved deviation](https://github.com/KD5UJC-XYZ/scarab/issues/474#issuecomment-6747536849)).** The reference takes the capacity in `Word32`. With a large override it wraps: 4,096 blocks of 64 KiB leave it 0 bytes of reference scripts, so it holds back every transaction that names one. It also rounds the number of blocks down at the top of the override's range. Scarab keeps the exact capacity (4,294,967,296 bytes of reference scripts in that example) and holds such transactions.
- **LocalTxMonitor replies always encode.** `GetSizes` sends a capacity or a size above 2^32 - 1 as 2^32 - 1; it used to fail with `Word32Range`. A measure of `GetMeasures` is sent as a CBOR integer of any size, a bignum above 2^64 - 1, as the reference's `encodeInteger` writes it, and the client reads one.
