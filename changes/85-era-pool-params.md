### Changed (era types, #85)

- A pool's registration parameters are the state's `StakePoolParams`, with the reference's field types (a pool key hash, a VRF key hash, an account address, owners as staking key hashes) and, in the Leios build's layout, its voting key; the certificates and the pools' future parameters hold them, so POOL uses them without conversion, and refuses parameters decoded for the other build's layout. The native snapshot's state is written with the same bytes. Dijkstra's pool registrations now read into the era types with their voting key, a chunked metadata URL included.
- Reading a stored ledger state is narrower for the pools' future parameters, by the owner's decision of 2026-11-19 (asked 19:18:13Z, decided 20:18:03Z) that it matches the reference: their metadata must be a record of a URL and a hash, the URL at most 64 bytes below protocol version 9 and 128 from it, a chunked hash read from protocol version 12 and a chunked URL only in the Leios build from 12, and their reward account's network must be 0 or 1. Each refusal is a typed error.
