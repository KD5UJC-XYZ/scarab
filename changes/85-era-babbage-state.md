### Added (era types, #85)

- Babbage has the state classes of the era types: its stake accounts (`EraAccounts` and the reference's `ShelleyEraAccounts`, with the pointer of the certificate that registered each account), its instant stake with the stake of pointer addresses (`EraStake`), its governance state (`EraGov`, over an era record of Shelley's governance state that keeps each proposed update with the bytes the node stores it by) and its stored outputs (`StoredTxOut`). The governance state is read from the node's flat record and written back over it identical. On every recorded Babbage state the classes read what the flat code reads, the governance state writes back byte for byte, and the instant stake changes as the reference's results and the flat code's do, pointer addresses among them. Babbage's certificate-state instance names Babbage's transaction body and comes with it. No rule uses these instances yet, so behaviour and the persisted format do not change.
