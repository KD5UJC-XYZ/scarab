### Changed (devnet e2e protocol versions)
- **`devnet.py e2e` drives the Conway protocol versions to the highest one the reference supports instead of two scripted hard forks.** Once the tip is in Conway the run asks the reference `GetMaxMajorProtocolVersion` (the `MaxMajorProtVer` of its consensus layer, 11 for cardano-node 11.1.3; no answer, a non-version or node-to-client below 21 fails the run) and proposes one chained HardFork action per version, voted by the pools alone during the bootstrap phase and by the DReps, the committee and the pools from version 10, within a time derived from `govActionLifetime`, the hop count and the epoch length. The run waits past its target epoch for the walk and for the checks of the versions it reached; `soak --governance-extended` keeps its scripted competing hard forks.
- **Version-specific checks are a registry** (`scripts/devnet/protocolversions.py`): the reference-input overlap cases (refused before 11, allowed from 11) and the VRF key-hash cases (from 11) are registered with the versions they apply to, run when the chain is at one of them and reported in `e2e-summary.json` (`extended.versionChecks`, `protocol`) with the version they ran at. They were hard-coded `pv < 11` and `pv >= 11` tests, and the two overlap cases were not judged.
- **A coverage guard fails `e2e` when the reference supports a Conway protocol version that no registered check covers** and that is not registered as having none, so a cardano-node release that raises the maximum forces a review of the registry. Unit tests of the registry, the guard and the walk need no Docker (`scripts/tests/test_protocol_versions.py`).
