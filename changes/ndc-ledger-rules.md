### Added (conformance)

- `tools/runMain xyz.kd5ujc.scarab.ledger.LedgerRulesMain` writes Scarab's report for the ledger-rules scenario of [node-diversity-conformance](https://github.com/pragma-org/node-diversity-conformance): each transaction fixture of the corpus is decoded by the mempool's decoder and applied by the MEMPOOL rule, scripts evaluated, on the ledger state the fixture declares, and its verdict is written as the scenario's schema names it. A transaction the mempool refuses only for a vote a block admits is judged by the LEDGER rule alone, as in a block. A refused transaction may fail several predicates at once and the report gives one name: by default (`--select expected-in-failures`) the report names the expected failure when Scarab raised it among others, and otherwise the first, which is the criterion cardano-node's report for the scenario is produced by; `--select first` always names the first failure, in the reference's order. The report never names a failure Scarab did not raise, and an accepted transaction is a pass whatever the fixture expects. A sidecar keeps every failure of each fixture with the names it maps to, and which rule chose the reported name; a fixture Scarab gives no verdict is left out of the report, which the site counts as failed.
