### Changed (era types, #85)

- Under the Leios build, every tick of a Dijkstra ledger state (a block's, the mempool's, the forger's) runs Dijkstra's epoch boundary on the era types: the ratification and enactment the DRep pulser reaches, the proposals with the enacted, competing and expired actions removed, the next epoch's parameters and the deposits returned, as the reference does; the node's earlier Dijkstra epoch rule is removed. The tick reads the stored governance state into the era's before it and writes it back after it, unchanged for every state the store holds, so nothing persisted changes. A stored governance state the tick cannot read, or one it could not write back, is no verdict on the block: it is not recorded as invalid and no peer is blamed. The release builds never enter Dijkstra, and Conway's tick is unchanged.
