### Added (peer metrics and churn, G1.2, #136)
- **The churn governor** (`peerChurnGovernor`): 3 s after start the root target is released (a head start for the local roots),
  then every 3300 s plus up to 600 s (fetch mode deadline) or 900 s plus up to 60 s (bulk sync) a round changes the targets one
  set at a time, in the reference's order, and waits for the counters or a timeout: it lowers the active target by 20% (at
  least one), restores it, and does the same for the established and the known peers. The steps for big ledger peers are left
  out until there are any (G1.3). `--churn-interval <Ns|Nm>` shortens the rounds for tests.
- **Peer metrics**: hot sessions report who is first with each header and block (two boards of 180 slots, the reference's
  `PeerMetric`); when the governor demotes hot peers it drops those with the lowest `upstreamness + fetchynessBlocks`
  instead of a random pick.
- **BlockFetch reads the fetch mode** (#144): in bulk sync a block another session has claimed is not requested; in deadline
  mode it may be, by up to `MaxConcurrencyDeadline` sessions (new configuration key, default 1 as in the reference).
- Log event `peerSelectionChurn`; metrics `scarab_peer_selection_churn_rounds_total`, `_churn_steps_total`,
  `_churn_wait_seconds`, `_peer_metrics_board_size`, `_backoff_seconds`; the `governor` devnet scenario.
