### Changed (mempool, measures and capacity)
- **The mempool measures a transaction before the ledger rules and holds a capacity of whole blocks, as the reference does.** A transaction over `maxTxSize` or `maxTxExUnits` is refused with `MaxTxSizeUTxO` / `ExUnitsTooBigUTxO` (both, when both are exceeded), and one whose reference scripts exceed 200 KiB with `ConwayTxRefScriptsSizeTooBig`, and only that failure is returned: a transaction that also spends spent inputs is no longer reported as "All inputs are spent". The capacity is a vector of bytes (size plus 4), execution-unit memory and steps and reference-script bytes: two blocks of the protocol parameters in force by default, and `--mempool-bytes` (or `MempoolCapacityBytesOverride`) rounded up to whole blocks; it follows a parameter change at the next revalidation, and LocalTxMonitor reports the capacity the pool enforces. A full pool is refused when any component would be exceeded.
- **The default mempool capacity is no longer 1 MiB.** Without `--mempool-bytes` the capacity is two blocks (`2 * (maxBlockBodySize - 1024)` bytes, 178,176 on mainnet parameters) of the parameters in force.
