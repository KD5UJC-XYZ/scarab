### Changed (mempool, intervene policy)
- **A transaction from a peer is held with the `is_valid` flag its scripts call for, as the reference does.** TxSubmission2 transactions are validated with `is_valid` forced to true; if a script then fails, the transaction is kept with `is_valid` false (and the submitter loses the collateral) instead of being refused, and a transaction claiming false whose scripts pass is held as valid. The relayed bytes differ from the received ones only in the flag byte; the transaction id is unchanged. LocalTxSubmission still validates the transaction as received and refuses a wrong flag with `ValidationTagMismatch`. `Mempool.add` and `MempoolState.add` take the `Source` of the transaction.
