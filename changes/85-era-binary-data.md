### Changed (era types, #85)

- The era types' outputs hold the reference's `Datum era`, an inline datum as an opaque `BinaryData`: read as data where an output is read from a block or a transaction, as the reference's `DecCBOR` reads it, and taken unread where it is read from the store, as its `MemPack` takes it. Only `BabbageTxOutRep.fromStored` can take one unread, which the type of its evidence enforces; its callers are trusted to pass an output read from the store, as the reference trusts its `MemPack`, until the store reads the era's outputs itself. The script contexts and the spending datum read it through `binaryDataToData`, whose failure, which only an inline datum taken unread can reach, is the node's own `Undecodable` where the reference raises `error`. Valid data and the persisted bytes are unchanged. A stored inline datum that is not data now gives the typed `Undecodable` where the era types' Plutus V1 translation gave `InlineDatumsNotSupported`, as the reference's strict `SJust` forces the decode first. The node still builds its contexts with the existing code.
