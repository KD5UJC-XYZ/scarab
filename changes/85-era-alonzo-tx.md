### Added (era types, #85)

- Alonzo's transaction has era types of its own (`AlonzoTx`, `AlonzoTxBody`, `AlonzoTxWits`, `AlonzoTxAuxData`, `AlonzoTxCert`), read by Alonzo's decoders and mirroring the reference's, with the genesis-delegation and instantaneous-reward certificates and the update proposal. The decoders read a map's keys in the order they are written, as the reference does, and refuse the PlutusV2 and PlutusV3 scripts of a witness set and auxiliary data as the reference refuses them at Alonzo. Every Alonzo transaction the repository records reads the same, field by field, as with the node's current decoder, and the Alonzo cases of the reference's decoder corpora are accepted and refused as the reference does. Nothing in the node uses these types yet, so behaviour and the persisted format do not change.
