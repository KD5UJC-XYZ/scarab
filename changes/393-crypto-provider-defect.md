### Fixed (crypto verification, #393)

- A crypto provider that fails or breaks its contract (Ed25519 witness or Byron block signature, VRF, KES, certificate signature) is no longer a rejected signature, proof or header. The rules return it as a typed `ProviderDefect`, and the node does what the reference does with the exception: on the block path (follower, chain selection, startup recovery, replay, the forger's own block) it stops with `Fatal.Unverifiable`, exit 7, without recording the block as invalid or blaming a peer; on the header-first path it closes that peer's connection, which is tried again later; on a local submission it closes that client's connection, and on a peer's transaction that peer's. Invalid signatures, proofs and certificates are still rejected as before. The same holds for the Byron ledger's own signatures (transaction witnesses, delegation certificates, update proposals and votes, #438), and a defect on the node's own forged block stops the forger instead of evicting the block's transactions.
