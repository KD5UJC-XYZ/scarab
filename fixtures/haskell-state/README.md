# Haskell ledger-state snapshots (`state`, `meta`, `tables`), one per era

Real `cardano-node` 11.1.3 ledger snapshots of the throwaway `devnet.py up-eras` cluster, one per
era from Byron to Conway, for the byte-round-trip tests of the Haskell ledger-state codec
(`HaskellStateCodecSuite` and friends). Each directory is `<era>-<slot>/` with the three files of a
UTxO-HD in-memory snapshot (`backend: utxohd-mem`, tables codec version 1):

| File | Contents |
|---|---|
| `state` | the `ExtLedgerState` CBOR: `[1, [summary, telescope]]` (version 1, hard-fork summary of every era so far, then the telescope whose current-era index is the era) |
| `meta` | the snapshot metadata JSON (`backend`, `checksum` of `tables`, `tablesCodecVersion`) |
| `tables` | the UTxO table (a few hundred bytes: the devnet holds three funded addresses) |

## How they were made

A running node writes a snapshot only after a rate-limited delay of 5 to 10 minutes (the 11.1.3
`SnapshotFrequency` policy: `sfaRateLimit = 600s`, `SnapshotDelayRange` 300 to 600 s, interval and
count settable as `LedgerDB.SnapshotInterval` / `NumOfDiskSnapshots`, the delay not), so the 8
minute era walk yields none (none appeared in a run with `SnapshotInterval: 25`). The snapshots
therefore come from the node's own tool `db-analyser`, which replays a ChainDB and writes the same
LedgerDB snapshot files at a chosen slot. No script and no configuration of the repository was
changed.

```sh
python3 scripts/devnet.py --name s8eras up-eras        # blocks until the first Conway block
# in the reference container (s8eras-ref), on a copy of node1's db without its ledger/ and lock:
mkdir /work/an && cp -r /work/env/node-data/node1/db /work/an/db && rm -rf /work/an/db/ledger/* /work/an/db/lock
cd /work/env
for s in 25 1000 1800 2300 3000 4000 4593; do
  db-analyser --db /work/an/db --store-ledger $s --in-mem --threshold 0.6 \
              --config /work/env/configuration.yaml
done
python3 scripts/devnet.py --name s8eras down
```

`--threshold 0.6` is the genesis-delegate signature threshold of the node configuration
(`PBftSignatureThreshold`); `db-analyser` does not read it from the file and its default (0.22)
makes the replay of the 3-delegate Byron epoch stop with `PBftExceededSignThreshold`. The snapshots
are stored as `<slot>_db-analyser/{state,meta,tables}`; the suffix is dropped here. Replay uses
block reapplication (`LedgerReapply`), the same ledger code path as a node.

## Verification

* Era: the decoded `state` is `[1, [summary, telescope]]`; the telescope's current-era index
  (`state[1][1][0][0][0]`) is 0, 1, 2, 3, 4, 5, 6 for Byron to Conway, and the hard-fork summary
  (`state[1][0]`) and the list of era/bound pairs (`state[1][1][1]`) have 1, 2, 3, 4, 5, 6, 7 entries,
  i.e. the number of eras entered so far. The Conway summary lists the era boundaries epochs 1, 4,
  5, 6, 8, 10, matching the `up-eras` timeline. A 40-line CBOR decoder in Python (no third-party
  code) consumed each file completely (consumed bytes = file size).
* Fresh keys and genesis are generated per devnet run, so the slots and hashes are those of this run
  only; the fixtures are not reproducible byte for byte, only in kind.
