# Sum6 KES tree-generation vectors

Sum6 KES key-generation vectors from `cardano-cli node key-gen-KES` (cardano-node 11.1.3 reference image).

Each row is `name  r1  vk1  vk0  vk`, all hex, taken from a throwaway key of a `cardano-testnet create-env`
sandbox: `r1` is the seed of the right depth-5 subtree stored in the signing key, `vk1` the root verification
key of that subtree as cardano-cli computed it, `vk0` the left one and `vk = Blake2b-256(vk0 || vk1)` the
`kes.vkey`. Regenerating the depth-5 tree from `r1` must give `vk1` (this fixes the seed-expansion convention),
and `vk` must be the hash of the pair. The rows hold seeds of a subtree of a sandbox key only, never a whole
signing key file.

Provenance and licence: generated by this project with `cardano-cli` from the cardano-node 11.1.3
reference image (IntersectMBO, Apache-2.0, not redistributed) from throwaway sandbox keys; the vectors
contain no third-party or private data. The repository's Apache-2.0 applies.

## Comparison and regeneration

`Sum6KesSigningSuite` reconstructs the right subtree from each retained throwaway seed and compares
the exact native `vk1`, then checks the parent-root commitment. These are generation-convention
vectors, separate from the public-header signature-verification corpus in
[`../sum6/README.md`](../sum6/README.md). They are not production credentials or a signature-validation
oracle. The exact TSV SHA-256 is listed in `SHA256SUMS`; verify it with:

```sh
(cd fixtures/kes-gen && sha256sum -c SHA256SUMS)
```

A new independent fixture requires an isolated throwaway `cardano-testnet create-env` sandbox using
the recorded reference release, with original public output and source/image identity archived.
Extract only the corresponding right-subtree seed and verification roots in the same five-column
schema; never copy a real operator's signing-key file. There is no maintained extraction script for
this historical corpus. Keep these original rows unchanged when adding new reference evidence;
the finite vectors do not establish every-period or shipped-binary equivalence.
