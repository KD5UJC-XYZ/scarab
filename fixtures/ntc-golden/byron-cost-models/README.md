# Byron-origin cost-model translation

Status: Current — a scoped native parameter-upgrade oracle and golden migration evidence.

`native.json` is the output of unchanged Haskell `upgradePParams` for Alonzo, Babbage and Conway,
using the exact `fixtures/eras/genesis` Alonzo and Conway inputs. Alonzo/Babbage retain only V1;
Conway adds V3. The Alonzo `extraConfig` V2 model is not part of a Byron-origin era translation.
The initial Mary parameters are empty: this probe establishes the cost-model fields, not complete
parameter or ledger-state equality. `provenance.json` pins inputs, image and installed sources;
all six parser/upgrade/CostModels files were byte-identical to ledger `f649f975`.

Replay every captured map and the native Conway CBOR without exclusions:

```sh
python3 scripts/oracle/genesis-cost-models/run.py --name scarab-genesis-cost-model-proof
```

`golden-migration.json` records the 25 changed rows and 68 exact CBOR spans in the 265-row parent
golden. An isolated baseline restoring only the former genesis merge reproduced every old row.
Every changed span removed exactly the complete genesis extraConfig V2 vector; V1/V3 remained
byte-identical to the independent native output. Replacing those spans in current raw answers
restored all original raw bytes. The other 240 rows did not change. The candidate was captured
separately; original genesis/block inputs and the original golden remained untouched until review.
This is a field-level migration proof, not a native oracle for every query or whole state.

Original input files remain in the eras corpus. Generated by this project; Apache-2.0.
