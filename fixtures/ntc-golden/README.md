# Node-to-client answers on the Conway states of the eras capture

`conway-answers.tsv` records what `QueryAnswers` answers to every ledger query on five Conway
states: the three Conway states of `fixtures/eras` (`conway-0` .. `conway-2`), and two built on the
last one (`rich`, `rich-genesis`) that hold what a three-block chain does not: DReps, a committee
and its state, one proposal of each kind, a completed pulser with its snapshot, delegations of every
DRep kind and credentials that sort across the byte ranges. `rich-genesis` has the pulser the
genesis seeds (no previous parameters, no completed pulser). `NtcGolden` builds the states and the
battery of queries.

One line per answer: `state TAB query TAB value`. The value is the hex of the answer (the item
inside `[result]`) or, above 2048 bytes, `sha256:` and its digest.

The bytes were recorded from `LedgerEncoders`, the encoders the answers were written with until
jump 1 of step 2 of the ledger-state mirror, whose bytes the devnet comparison with the reference
node `cardano-node` 11.1.3 had proved (`ntc` scenario, 987/987 outside the documented gaps). They
are the contract of that jump: the answers are written by the Haskell state codec now, and must be
the same bytes. `NtcGoldenSuite` compares them; `QueryGoldenSuite` does the same for the reference
node's own answers (`fixtures/devnet/lsq/golden.json`).

Regenerating them is a change of the answers, which needs the reasons (a reference comparison), not
a refresh:

```sh
sbt 'set node / Test / run / baseDirectory := file(".")' 'node/Test/runMain xyz.kd5ujc.scarab.node.ntc.NtcGolden'
```

Generated by this project from the eras capture; no keys, no third-party data. Apache-2.0.

## Changes since the first recording

- J1.1 (pulser `EnactState`): `DebugEpochState` and `DebugNewEpochState` of `rich-genesis` (a state
  with no completed pulser) were re-recorded. The mirror's pulser used to be the node's parameters
  with treasury 0; it is now the one `GetRatifyState` and `GetGovState` report
  (`ConwayEpoch.reportedPulser`: the real treasury, and before the first boundary the parameters of
  the era translation), which those queries had matched against the reference all along. The states of
  the capture and `rich` did not change.
- J2.3 (previous parameters of the first Conway epoch): `DebugEpochState`, `DebugNewEpochState`,
  `GetGovState` and `GetRatifyState` of `conway-0` .. `conway-2` were re-recorded (the three Conway
  states of the capture are in the first epoch of Conway; `rich` and `rich-genesis` did not change).
  The previous parameters of a state that has just entered Conway now carry the fields Conway
  introduces, and so does the previous-parameters copy in the pulser's enact state: the reference
  translates the previous parameters with the current ones (`translateGovState`,
  `Conway/Translation.hs:165-178`; `upgradePParams` sets the fields from the Conway genesis) and its
  first Conway EPOCH makes them the previous parameters (`Conway/Rules/Epoch.hs:324`), where the
  node had translated only the current ones. Found by comparing the era-indexed tick with the old
  rules on the capture (`docs/findings.md`); no reference answer for such a state existed (the
  devnet `ntc` scenario starts in Conway).
