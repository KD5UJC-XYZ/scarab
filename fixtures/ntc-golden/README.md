# Node-to-client answers on the Conway states of the eras capture

Status: Current — project-generated byte regression answers, distinct from native oracle captures.

`conway-answers.tsv` records the historical ledger-query battery on five Conway
states: the three Conway states of `fixtures/eras` (`conway-0` .. `conway-2`), and two built on the
last one (`rich`, `rich-genesis`) that hold what a three-block chain does not: DReps, a committee
and its state, one proposal of each kind, a completed pulser with its snapshot, delegations of every
DRep kind and credentials that sort across the byte ranges. `rich-genesis` has the pulser the
genesis seeds (no previous parameters, no completed pulser). `NtcGolden` builds the states and the
battery of queries. This inventory is not the complete current LocalStateQuery surface.

One line per answer: `state TAB query TAB value`. The value is the hex of the answer (the item
inside `[result]`) or, above 2048 bytes, `sha256:` and its digest.

The bytes were recorded from `LedgerEncoders`, the encoders the answers were written with until
jump 1 of step 2 of the ledger-state mirror, whose bytes the devnet comparison with the reference
node `cardano-node` 11.1.3 had proved (`ntc` scenario, 987/987 outside the documented gaps). They
are the contract of that jump: the answers are written by the Haskell state codec now, and must be
the same bytes. `NtcGoldenSuite` compares all 265 rows with exact subject/query-key inventory, rejecting
malformed values, duplicate keys, missing rows and stale extra rows; `QueryGoldenSuite` does the same for the reference
node's own answers (`fixtures/devnet/lsq/golden.json`).

Regenerating them is a change of the answers, which needs an independent reference comparison and
a field-level explanation. Preserve the original file and write a separate candidate; the recording
entry point below currently writes the tracked path directly. Run it only in a disposable isolated
worktree after archiving the original, then copy out the candidate for comparison. Its output-path
hardening is tracked by [#294](https://github.com/KD5UJC-XYZ/scarab/issues/294); do not invoke it
in the authoritative checkout or treat its output as an independent oracle:

```sh
bash scripts/sbtw 'set node / Test / run / baseDirectory := file(".")' 'node/Test/runMain xyz.kd5ujc.scarab.node.ntc.NtcGolden'
```

Run that command inside `scarab-jdk:local`, as CONTRIBUTING requires.

These five bounded states do not establish every query/era combination, native full-state parity or
completeness of imported likelihood history. See the change-specific provenance below. Generated
from synthetic chain state; no signing keys. Apache-2.0.

## Changes since the first recording

- J1.1 (pulser `EnactState`): `DebugEpochState` and `DebugNewEpochState` of `rich-genesis` (a state
  with no completed pulser) were re-recorded. The mirror's pulser used to be the node's parameters

  (`ConwayEpoch.reportedPulser`: the real treasury, and before the first boundary the parameters of

- J2.3 (previous parameters of the first Conway epoch): `DebugEpochState`, `DebugNewEpochState`,
  `GetGovState` and `GetRatifyState` of `conway-0` .. `conway-2` were re-recorded (the three Conway
  states of the capture are in the first epoch of Conway; `rich` and `rich-genesis` did not change).
  The previous parameters of a state that has just entered Conway now carry the fields Conway
  introduces, and so does the previous-parameters copy in the pulser's enact state: the reference
  translates the previous parameters with the current ones (`translateGovState`,
  `Conway/Translation.hs:165-178`; `upgradePParams` sets the fields from the Conway genesis) and its
  first Conway EPOCH makes them the previous parameters (`Conway/Rules/Epoch.hs:324`), where the
  node had translated only the current ones. Found by comparing the era-indexed tick with the old
  rules on the capture (`docs/findings.md`); no reference answer for such a state existed (the
  devnet `ntc` scenario starts in Conway).
- J2.9 (the old rules removed): the states of the capture are now the era-indexed rules' own, where
  they were the old rules' flat state put through the mirror. Re-recorded: the lines that take an
  argument drawn from the state (`GetFilteredDelegationsAndRewardAccounts some`,
  `GetStakeDelegDeposits some`, `GetSPOStakeDistr some`, `GetPoolDistr2 some`, and the DRep ones),
  because the arguments are now chosen by sorted hash and not by the order of a map (the order of a
  map is the order the state was built in, which differs between the two builders), and every answer
  that depends on the two synthetic states, `rich` and `rich-genesis` (their `DebugEpochState`,
  `DebugNewEpochState` and stake-distribution answers: the enrichment is laid on the flat ledger
  state read back from the mirror, whose pool snapshot, pool distribution and delegations are those
  of the new rules). No answer on `conway-0` .. `conway-2` that takes no argument from the state
  changed, byte for byte, and the reference comparison of the answers is the devnet `ntc` scenario.
