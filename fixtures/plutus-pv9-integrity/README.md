# Synthetic PV9/V3 integrity equality packet

28 reference-decoded cases:23 observed commitment matches and5 mismatches, plus2 malformed commitment decoding rejections. Existing18 transaction vectors cover only3 distinct integrity preimages. Additional cases independently observe original-byte preservation and stale/repaired commitment pairs, rather than counting repeated preimages as additional encoding coverage.

See [Scala integrity contract](../../translator/INTEGRITY.md). This is one commitment equality check, not script success, phase1 validity or full ledger validation. No Plutus evaluation ran in this reference probe. The old context/evaluation helper was not changed.

The reference Kernel derives languages using `mkAlonzoStAnnTx/asatPlutusLanguagesUsed`, then applies `mkScriptIntegrity`, `hashScriptIntegrity` and isolated `checkScriptIntegrityHash`. It exports exact memoized redeemers, semantic datum count, original datum bytes and omitted datum domain, reconstructed language view, complete preimage, optional supplied/computed hashes and diagnostic. Derived languages are then checked to be exactlyV3. No caller constant substitutes for reference script resolution.

Cases include missing/zero/flipped commitments, redeemer7-to8 with stale/repaired commitment, and definite-to-indefinite redeemer map with stale/repaired commitment. The reference accepts the indefinite map and preserves its bytes. Both repaired cases replace only the body commitment using the reference result, preserving witness memoization. Outer witness-map reversal, fee+1 and inline pre-state datum changes retain the same commitment preimage. Fee+1 is deliberately not a value-conservation or valid-transaction claim. Wrong-width31/null commitments reject, rather than yielding equality evidence.

`vectors.json` separates packet input, intended mutation metadata and observed reference results. Scala tests use the actual reference domains/equality, compare them independently, and demonstrate that normalizing the indefinite redeemer map would yield the wrong digest. The expectedMatch metadata is never the Scala oracle.
